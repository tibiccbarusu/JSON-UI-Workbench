# JSON UI Studio — ローカル版ユーザーガイド

対象は今回の Revision 23 を含むローカル版です。Minecraft Bedrock のリソースパックを読み込み、Classic JSON UI の表示・原文編集・要素配置・依存ファイル付き書き出しを行います。ZIP の展開、継承解決、草稿の再計算などはローカルの Node.js で処理します。

## 1. 起動する

Windows では、配布 ZIP を展開したアプリのフォルダーにある `start.bat` を実行します。初回の Node.js の準備とサイトの起動を同じ BAT が担当します。初回の取得にはインターネット接続が必要になる場合があります。

BAT が開いた URL を使用してください。`file://` や Python の静的サーバーで開く方法では、ローカル版の Node API と原文編集機能を利用できません。起動に問題がある場合は同梱の `README-START-JA.md` と `local-node/START-ja.md` を参照します。

## 2. パックを読み込む

1. 左の「1 · パックを読み込む」を開き、通常パックを選びます。
2. バニラの継承元、文字、画像が必要な場合は、同じ欄のバニラ基底にも対象版のパックを追加します。バニラ単体でも UI を選べます。
3. 読み込み中は処理状態を確認できます。停止するときは読込欄のキャンセルを使います。

ZIP と MCPACK に対応し、MCADDON は非対応です。ファイル名だけでなく内容も検査します。元のパックを直接上書きする操作ではありません。外す・差し替える操作は作業対象を変更します。

数百 MB のパックでも必要な情報を Node 側で索引化・遅延読み込みします。ただし、容量、エントリ数、展開比、処理時間の有限上限があります。エラーの場合は理由を確認し、無制限に再試行しないでください。

## 3. ファイルと UI 定義を選ぶ

左の「2 · ファイルと定義を選ぶ」で JSON UI ファイルを選び、その下の定義一覧からプレビューする UI を選びます。1 ファイルに複数定義がある場合も個別に選択できます。「3 · 選択したUIをプレビュー」で中央へ表示します。

検索は候補を絞り込む操作です。検索しただけでは現在の選択を別の定義へ変更しません。選択中の定義が検索結果から外れた場合は別表示します。多数の候補は 100 件ずつページ送りできます。

別ファイルの継承元は読み込んだパック構成から解決します。必要な継承元が不足する場合は、対象版のバニラ基底を追加してください。索引にないファイルは「索引・手動パス・詳細状態」から手動パスで指定できます。

Pocket の定義は「Pocket / 解析のみ」と表示され、読み込みと索引を保持します。Pocket のプレビューは停止します。手動パスを使っても Pocket のプレビュー禁止は解除されません。Classic の定義を選んで表示してください。

## 4. 6 つのタブを使う

| タブ | 主な操作 |
|---|---|
| ホーム | UI 一覧、ファイル検索、プロパティ、画面に合わせる、左右パネルを閉じて集中 |
| 編集 | 複数選択・グループ、編集範囲と対象、要素追加、原文への入口 |
| 表示 | ズーム、端末サイズ、UI スケール、表示言語、通常/構造表示、動作確認 |
| データ | 右側の原文、プレビュー状態、継承・参照を開く |
| 書き出し | UI 選択、依存検査、パック情報・アイコン設定、MCPACK 保存 |
| 診断 | 詳細診断、反映済み状態の再確認、ログの一括保存 |

左は通常パック・UI の一覧、中央はキャンバスです。右は必要なときに開き、「プロパティ / 原文 / 状態 / 参照 / 診断」を切り替えます。左右の閉じるボタンを押しても設定や編集内容を破棄しません。パネル境界で幅を調整できます。

要素ツリーやサンプル・旧詳細エディタの入口は「ホーム」→「詳細ツール」です。通常の作業画面では折りたたまれています。解決済みプレビューの要素は、表示モデルを直接書き換えず右側の原文編集から変更します。ツリーの直接複製・並び替え等が無効になる場合があります。

## 5. 配置を編集する

上部の「編集」で編集モードに切り替え、キャンバスの要素を選択します。初期設定は「この UI だけ」「見た目の部品だけ」です。

- 要素をドラッグすると、原文へ確定する前に草稿プレビューが自動更新されます。
- Shift＋クリックは複数選択、Alt＋クリックはグループ内の単体選択です。「範囲を選択」も使用できます。
- Alt＋ドラッグはキャンバスの表示位置を動かします。
- 右のプロパティで実際の変更先と影響範囲を確認できます。
- UI の画像と動作を一緒に移動する場合は「操作要素全体」を選びます。生成された枠や共通部品は、対象範囲を確認してから編集します。

「この UI だけ」は現在の定義に変更を限定します。「共有元を編集」は同じ定義を使う他の UI にも変更が届きます。未確定の操作がある間は編集範囲の切り替えを停止します。先に確定または破棄してください。

要素の追加・継承変更・削除・直接 JSON 編集は「共有元を編集」で利用できます。追加は種類を選び、追加先の親を選択してキャンバスをクリックします。追加後の文字・テクスチャ・動作などはプロパティで確認してください。削除は影響を検査してから確定します。

## 6. プレビューと原文への確定を区別する

上部の「JSON UIに確定」は、草稿の変更を Node の作業領域の原文へ書き込む操作です。プレビューの移動・配置を表示するために毎回押す必要はありません。元の ZIP 自体は変更しません。

未確定件数とプレビューの再計算状態を上部へ表示します。更新に失敗した場合は「変更の管理」→「草稿プレビューを再計算」で再試行できます。「未確定の変更を破棄」は原文に確定する前の変更を取り消します。

「元に戻す」「やり直す」は未確定操作と原文の編集履歴を扱います。グループの設定履歴は別で、「編集」→「グループ設定」に保存・読み込み・戻す・やり直すがあります。

草稿の配置や原文入力が未確定の間は、端末サイズ、UI スケール、表示言語、プレビュー状態などの変更を停止します。編集中の座標の前提を変えないためです。表示ズーム、パネル開閉、詳細を見る操作は引き続き利用できます。

## 7. 原文を編集する

「編集」→「その他」→「原文データ」、または「データ」→「原文を表示」で右の原文を開きます。プレビューモードでは読み取り用です。編集モードの直接 JSON 編集は「共有元を編集」を選びます。

原文の入力中はその文章を草稿として保持します。検証・適用前の不正な JSON を正しいプレビューとして扱いません。必要に応じて原文を適用または取消し、配置の草稿とは別の状態であることを確認してください。

同じ相対パスが通常パックとバニラにある場合は、現在の原文がどちらの層に属するかを確認します。継承元や共有部品への変更は他の UI に影響する場合があります。

## 8. 表示条件・最大化・動作確認

「表示」のズームは見せ方だけを変えます。UI スケールと端末プリセットは論理的な表示条件を変えます。UI スケールは自動または 1〜6 倍、端末プリセットは 1280×720、1920×1080、2560×1440、3840×2160 を選べます。

最大化しても上端の「タブ・コマンド」から操作できます。マウスを上端へ移す、ボタンを押す、F6 を押す方法があります。「コマンドを固定」で常時表示し、Esc または「最大化を終了」で戻ります。終了時は開始前のズーム・位置と左右パネルの開閉を復元します。作業中に選んだ右タブや編集内容はそのまま保持します。

「表示」→「再生・アニメーション」には再生、一時停止、時間指定、イベント選択、1 コマ送り、表示の再計算があります。「3Dモデル・音声」には対応モデルと音声の設定があります。未対応のモデルや本人のスキン・装備・Persona を再現できたとは扱いません。

動作確認を ON にすると、対応するボタン・入力欄・スロットの代表動作を試せます。「データ」の状態入力から表示条件を指定できます。ゲームが実行時に渡すデータ、collection、factory などには代表状態や未対応範囲があり、Minecraft 実機との一致とは区別します。

## 9. バニラ・不足素材・診断

文字・テクスチャ・継承元を含めて確認するには、対象 Bedrock 版に対応する公式バニラ full パックを使用します。画像等を含まない min パックだけでは視覚確認の基準を満たしません。

左のバニラ「版設定」から右の診断へ移動し、対象版・配布元 release・channel を確認します。構造や明示した版情報が不一致の場合は利用を停止する場合があります。版情報の警告がないこと自体は実機での合格を意味しません。

「欠落している素材・参照を確認」、または「データ」→「継承・参照」で未解決情報を確認します。診断の警告は、正当な動的参照を扱う際にも表示される場合があります。エラーや書き出し検査結果を読み、成功・警告・停止を区別してください。

問題を報告するときは「診断」→「ログを一括保存」を使います。ブラウザ・Node・起動ログの直近情報をまとめます。通常の 500 診断・200 操作を保持し、大きい情報には容量・構造の上限と省略情報があります。Node に接続できない場合はブラウザ記録だけを保存します。秘密・原文・画像本体の既知キーは除去し、ゲーム状態の名前や相対パス等の診断に必要な情報は残します。

## 10. リソースパックを書き出す

1. 必要な配置を「JSON UIに確定」で確定します。
2. 「書き出し」で「現在の UI を追加」を押します。複数の UI を順に追加できます。
3. パック設定を開き、名前、説明、版、作者、PNG アイコンを必要に応じて指定します。
4. 「依存範囲を検査」で必要な JSON・画像・音声・翻訳・字体などと未解決項目を確認します。
5. 「リソースパックを保存」で MCPACK を保存します。

選択した UI の入口と依存を保持する書き出しです。無関係な UI を不用意に上書きしないよう、生成したファイル一覧を確認してください。動的な依存や文字関連ファイルを安全側で広めに含める場合があります。アイコンの読み込み中は検査・保存を停止します。アイコン選択に失敗した場合は直前の有効な設定を保持し、理由を表示します。

パックの出力とグループ設定の保存は別です。ページの再読み込みでブラウザの作業状態は失われるため、終了前に必要な出力を保存してください。

## 11. キーボード

| キー | 操作 |
|---|---|
| Ctrl+K / ⌘K | 左を開きファイル検索へ移動 |
| Ctrl+F / ⌘F | 詳細ツリーを開き要素検索へ移動 |
| Enter / ↓ | ファイル・定義検索から一覧へ移動 |
| Esc | 通常表示の検索条件を解除 |
| Ctrl+Alt+1 / ⌘⌥1 | 左パネルを開閉 |
| Ctrl+Alt+2 / ⌘⌥2 | 右パネルを開閉 |
| 左右矢印 / Home / End | フォーカスがあるタブを切り替え |
| F6 | 最大化中のコマンドとキャンバスを切り替え |
| Esc | 最大化を終了。プレビューの文字入力欄・IME 変換中はその処理を優先 |
| Shift+F10 / Menu | キャンバスの選択要素の操作メニュー |
| Ctrl+G / Ctrl+Shift+G | キャンバスの編集モードでグループ化・解除 |
| Ctrl+Enter / ⌘Enter | キャンバスの編集モードで JSON UI に確定 |

## 12. コマンドモード

アプリのフォルダーで PowerShell を開いて実行します。

```powershell
node .\local-node\cli.mjs help
```

`node` が見つからない場合は、BAT が用意したアプリ専用 Node を指定できます。

```powershell
.\.jsonui\runtime\node.exe .\local-node\cli.mjs help
```

`import`、`list`、`definitions`、`read`、`edit`、`undo`、`redo`、`validate`、`export`、`diagnostics` などの CLI 入口を利用できます。正確な引数は `help` と同梱の `local-node/CLI-ja.md` を確認してください。CLI はセッションファイルを用い、ブラウザの未確定編集を自動共有しません。

## 13. 困ったとき

- UI が空白: Pocket の選択、原文検証中、Node の処理状態、未解決継承元を確認します。
- 移動後に草稿が更新されない: 上部の状態を確認し、「変更の管理」から再計算します。処理の確定結果が不明な場合は、勝手に同じ編集を再送しません。
- 文字・画像が欠ける: バニラ基底の版と full パックを確認し、参照・診断を保存します。
- 読込・保存に失敗: 表示されたエラーと容量制限を確認し、ログを保存します。
- 実機と異なる: パック版、画面サイズ、GUI スケール、表示言語、ゲーム状態を揃えて比較します。静的検査やローカルプレビューだけで実機一致と判断しません。

同梱の `DEMO_SCENARIOS.md`、`ACCEPTANCE_CHECKLIST.md` は検査手順の補助資料です。旧版の記述と現在画面が違う場合は、本ガイドのローカル版の入口を使用してください。
