- アプリの起動、合成リソースパックの読込み、ファイル・定義の選択、プレビュー描画。
- 現行・旧版アイテムIDプロファイルの切替。
- アカシア看板と板材を別色の合成画像で区別する、実HTTP・PNG出力の回帰試験。
- 欠けた任意のSteve参照が、読み込んだ独自playerモデルを妨げないこと。
- 合成フォントのHTTP取得、複数Unicodeシート、非同期キャッシュ、欠字、再試行、RGBA比較。
- 名前探索、collection境界、文字位置、限定的なアニメーション診断。
- 不完全な評価の停止、明示的な部分出力、長い証拠IDの復元、概要JSON、状態更新時のモデル再利用。
- 公開用ファイルの選別、固定した依存関係からのインストール、必要ファイルの存在、配布ファイルのハッシュ。

## 件数の読み方

`npm run test:release` はNodeのテスト群に続いて共通エンジンの試験を実行します。
2つの件数を分けて記載し、スキップは成功に含めません。原版のゲーム素材を必要とする
次の5ファイルは公開パッケージと公開試験から除外しており、スキップ数にも含まれません。

- `local-node/tests/horse.test.mjs`
- `local-node/tests/native-player-default.test.mjs`
- `local-node/tests/texture-value37.test.mjs`
- `editor-core/tests/ui-interaction-actions.node.test.mjs`
- `editor-core/tests/ui-audio-main12.node.test.mjs`

ほかにも、非同梱の実フォント・過去の私的fixture等との照合だけは、欠落理由を付けて
スキップされます。同じ機能を検査できる箇所には独自の合成素材による試験を残しています。
合成素材の検査は、Minecraftの実字形や実機画素の一致を証明しません。

## 再実行

新しく展開した公開用フォルダーで、次を実行します。

```sh
npm ci --ignore-scripts
node scripts/release/audit-public.mjs --verify-manifest
npm run check:package
npm run test:release
npm start
```

`--verify-manifest` は配布物を編集する前の完全性検査です。自分でコードを編集した後の
公開監査には、同じコマンドからこの引数を外してください。

GitHub Actionsには Node.js 22.14.0 で公開ファイル監査と回帰試験を実行する設定を
同梱しています。今回GitHubにpushしてActionsを実行したわけではありません。

## 実機との境界

成功はWorkbench内部の機能・描画・配布構成に対する結果です。ゲーム内での生成、
クリック、フォーム返却、保存・再入場、FPS、全端末互換性を確認した結果ではありません。
これらが未検証の場合、プレビューの成功だけで実機一致の判定を成功にしません。

詳しい修正範囲は [資料と改修の対応](REPORT_TRACEABILITY_JA.md) を参照してください。
