JSON UI Workbench 0.16.1 — 日本語説明書

English · 仕様書 · 注意事項 · ライセンス

このアプリは、Minecraft Bedrock のリソースパックに書かれた Classic JSON UI を読み、見た目と代表的な状態をゲームの外で調べるツールです。ゲームを起動したり、アドオンの JavaScript を実行したりするものではありません。まず付属の小さな例で「取込み → 画面選択 → プレビュー → 編集 → 書出し」を試してください。

対応するのは Classic UI のプレビューです。Pocket UI・スマートフォンで通常使われるタッチ向け UI のプレビューには対応していません。 この配布物は PC 上の Node.js で使う構成で、スマートフォン用アプリでもありません。端末の種類と Minecraft の UI プロファイルは別の条件です。詳しくは 注意事項 を参照してください。

1. 最初に選ぶ使い方

使いたい方法 入口 向いている作業
ターミナルにコマンドを入力する CLI・本書の標準手順 検査、画像作成、原文編集、パック書出し
プログラムから繰り返し呼び出す Node API 同じパックの繰り返し描画、AI との連携
Python 等から HTTP で呼び出す HTTP API 常駐するローカルサービスへの要求
マウスで見ながら編集する GUI・実験版 手動の確認と編集。未完成なので結果確認が必要

npm start は CLI の案内を表示して終了します。ブラウザーを開くには npm run gui を使います。従来の start.bat も GUI 用の互換入口です。CLI と API は自動でブラウザーを開きません。

2. インストールして準備する

  1. 配布 ZIP をすべて展開します。ZIP の中から直接実行せず、たとえば C:\Tools\jsonui-workbench-0.16.1 に置きます。
  2. Node.js 公式サイトから 22.14.0 以上の対応する Node.js と npm を用意します。初期検証の基準は Node.js 22.14.0 です。
  3. Windows では、そのフォルダーをエクスプローラーで開き、アドレス欄に powershell と入力して Enter を押します。これで、このフォルダーを作業場所にしたターミナルが開きます。
  4. 次を一行ずつ実行します。
node --version
npm --version
npm ci --ignore-scripts
node local-node/cli.mjs help

npm ci は同梱の package-lock.json に従って依存を入れます。--ignore-scripts は依存のインストール時スクリプトを実行しない指定です。初回はパッケージ取得の通信が必要です。既存の node_modules は npm ci により置き換わるので、自分の別プロジェクトでは実行しないでください。JSON と SVG の検査とは別に、PNG には任意依存の @napi-rs/canvas が必要です。

Windows で npm.ps1 が実行ポリシーにより拒否されたら、同じフォルダーで npm.cmd ci --ignore-scripts、npm.cmd run gui のように npm.cmd を使えます。実行ポリシーを変更する必要はありません。

Windows で「node が認識されない」と出たら、インストール後にターミナルを開き直して node --version を確認します。start.bat がアプリ専用 Node を用意している場合は、node の代わりに .\.jsonui\runtime\node.exe を指定できます。GUI 用ランチャーだけでは npm と PNG 依存の導入まで完了したとは限りません。

macOS/Linux ではターミナルで展開先へ cd し、同じ node と npm のコマンドを使います。本書のコマンド中の / は PowerShell と POSIX シェルの双方で使えます。Windows 固有の Get-Content や Invoke-RestMethod は POSIX シェルのコマンドではありません。

3. ファイルの場所と名前を区別する

例 意味
outputs/manual-demo.mcpack PC 上の入力パック。通常の相対パスは、現在の作業フォルダーが基準
outputs/manual-session.json CLI の作業記録。元パックの場所・ハッシュ・設定・編集差分を保存
ui/manual_demo.json パックの中の UI ファイル。PC 上に同名ファイルがなくてもよい
manual.screen ファイルの中の UI 定義名。名前空間 manual と定義 screen の組合せ
/screen/controls/2/card JSON Pointer。原文 JSON の中の編集対象を指定する経路

パスに空白がある場合は "C:\My Packs\sample.mcpack" のように引用符で囲みます。以後は毎回同じ --session を指定してください。省略すると、現在の作業フォルダーにある .jsonui-cli/session.json が使われます。

4. 付属の例で初めてのプレビューを作る

この例は、本書用の JSON、白い 1 ピクセルの画像、付属の人工 OGG 音を使います。Minecraft の画像・フォントは必要ありません。文字を含まない小さな画面なので、PNG の環境確認にも使えます。ゲームの中でフォームを開く完成アドオンではありません。

node docs/release/manual/examples/build-demo.mjs
node local-node/cli.mjs import --pack outputs/manual-demo.mcpack --session outputs/manual-session.json
node local-node/cli.mjs list --session outputs/manual-session.json
node local-node/cli.mjs definitions --file ui/manual_demo.json --session outputs/manual-session.json
node local-node/cli.mjs settings --file docs/release/manual/examples/settings-demo.json --session outputs/manual-session.json

build-demo.mjs は outputs/manual-demo.mcpack を新しく作ります。同名ファイルがあると停止し、勝手に上書きしません。やり直すときは、別名を指定します。

node docs/release/manual/examples/build-demo.mjs outputs/manual-demo-2.mcpack

一覧で ui/manual_demo.json と manual.screen を確認したら、次を実行します。

node local-node/cli.mjs validate --file ui/manual_demo.json --definition manual.screen --strict-semantics --session outputs/manual-session.json
node local-node/cli.mjs preview --file ui/manual_demo.json --definition manual.screen --frame 0 --format json --strict-semantics --out outputs/manual-frame.json --session outputs/manual-session.json
node local-node/cli.mjs preview --file ui/manual_demo.json --definition manual.screen --frame 0 --format svg --strict-semantics --out outputs/manual-frame.svg --session outputs/manual-session.json
node local-node/cli.mjs preview --file ui/manual_demo.json --definition manual.screen --frame 0 --format png --strict-semantics --out outputs/manual-frame.png --session outputs/manual-session.json

outputs/manual-frame.png を開くと、暗い背景、上の横帯、左のカード、下のスイッチが見えます。右側の詳細は、スイッチを操作するまで非表示です。幅 640・高さ 360・UI 倍率 2 の設定です。倍率 2 では、UI 内の 1 単位が出力画像の約 2 ピクセルに対応します。

出力 何を確認するか
JSON 解決済みの値、フレーム・矩形・binding・診断を詳しく見る
SVG 要素の矩形と配置を確認する図。素材・文字を再現した画像ではない
PNG 対応するテクスチャやフォント等を使って描いた画像

通常は、同名出力があると止まります。自分で置き換えてよい出力だけに --force を付けます。元パックとセッションを出力先にすることは --force でもできません。

5. 自分のパックと状態を調べる

手順は例と同じです。import の入力を自分の ZIP/MCPACK/MCADDON に変え、list → definitions の順で 実在するファイルと定義を探します。通常パックは --pack、バニラ参照パックは --vanilla です。両方を同時に指定することもできます。参照パックは自分が利用する権利を持つものを用意してください。

node local-node/cli.mjs import --pack "C:/MyPacks/addon.mcaddon" --vanilla "C:/MyPacks/reference.zip" --session outputs/my-session.json
node local-node/cli.mjs list --session outputs/my-session.json

MCADDON にリソースパック候補が複数あるときは、診断に出た header UUID を --resource-pack で指定します。最初の候補を勝手に選びません。参照パックや文字グリフが足りない場合、既定の PNG は停止します。JSON/SVG で構造を調べるか、必要な正当な参照素材を追加してから再試行してください。

ゲームから取得できない値には、代表状態を与えます。たとえば次を UTF-8 の outputs/state.json として保存します。

{
  "form": {
    "type": "action",
    "title": "Sample",
    "body": "Choose an item",
    "buttons": [{ "text": "Continue" }, { "text": "Close" }]
  }
}

node local-node/cli.mjs settings --state-file outputs/state.json --replace-state --session outputs/my-session.json

これは プレビュー用のデータです。フォームを実機で開くものではなく、読み込んだパックに欠けている定義を自動で作るものでもありません。--replace-state は以前の代表状態とローカルトグル状態を置き換えます。高度な生データは設定の mock_data / collections を使用します。型付き state との書き方・競合条件は 仕様書 を確認してください。

アニメーションの時刻は frame / fps 秒です。--frame 30 --fps 60 は 0.5 秒、--frame 0 は開始時です。PNG は時刻を省略すると開始約 1 秒後を使用するため、比較には時刻を明示してください。--strict-animation を加えると、アニメーション品質に未対応・不明状態が残る場合も停止します。

6. 検査結果を読む

CLI は通常、成功・失敗を JSON 1 件で返します。ok: true と終了コード 0 が処理の成功、ok: false と非ゼロ終了コードが失敗です。PowerShell では直後の $LASTEXITCODE を確認できます。案内文字列が欲しい場合は help、説明を英語にしたい場合は --language en を使います。

画像ができただけで合格と判断せず、quality、stage_diagnostics、diagnostics を確認してください。passed は対応範囲で計算できたこと、unknown は未対応・観測不足等が残ること、failed は不整合を検出したこと、not_evaluated は未評価を表します。quality.native_properties は 記録済みの非対応プロパティの検査で、Minecraft の全仕様を検査したという意味ではありません。

--strict-semantics は選択した UI の解決・行参照・表示入力 binding 等の不明状態を許可しない指定です。既定の PNG も、対応範囲の未解決素材等が残れば止まります。調査目的で不完全な画像が必要な場合だけ --allow-partial を使います。厳格検査の指定が優先されるため、これだけでは strict による失敗を解除できません。complete / preview_complete の真偽は 実機の全画素・操作・音の一致を保証しません。

7. 原文を編集して、取り消し・書出しを行う

まず付属例のカードを右へ 12 単位動かします。

node local-node/cli.mjs edit --operation docs/release/manual/examples/move-demo.json --session outputs/manual-session.json
node local-node/cli.mjs preview --file ui/manual_demo.json --definition manual.screen --frame 0 --format png --strict-semantics --out outputs/manual-edited.png --session outputs/manual-session.json
node local-node/cli.mjs undo --session outputs/manual-session.json
node local-node/cli.mjs redo --session outputs/manual-session.json

付属の move-demo.json は /screen/controls/2/card の offset を [36, 56] にします。offset はアンカーからの位置であり、画面の絶対ピクセルではありません。編集はセッションへ保存され、入力 MCPACK は変わりません。

ファイル全体を自分のエディターで編集する場合は、いったん原文を取り出します。

node local-node/cli.mjs read --file ui/manual_demo.json --out outputs/manual-authored.json --session outputs/manual-session.json

outputs/manual-authored.json を編集して UTF-8 で保存したら、反映します。

node local-node/cli.mjs edit --file ui/manual_demo.json --text-file outputs/manual-authored.json --session outputs/manual-session.json

不正な構文等の拒否時は、直前の確定済み編集を保持します。新しい編集を確定すると redo の履歴が消えます。undo には件数・容量上限があり、設定変更や UI 選択は undo の対象外です。

最後に依存関係を確認して、新しいパックを書き出します。

node local-node/cli.mjs export --file ui/manual_demo.json --definition manual.screen --plan --out outputs/manual-export-plan.json --session outputs/manual-session.json
node local-node/cli.mjs export --file ui/manual_demo.json --definition manual.screen --out outputs/manual-selected.mcpack --session outputs/manual-session.json

書出しは 選んだ UI と必要な依存が対象です。入力アドオンの全ファイル、BP スクリプト、世界やプレイヤーの状態を丸ごと保存するものではありません。依存を解決できない場合は停止します。パック名等の指定と、追加・削除・継承の操作形式は 詳細 CLI ガイド を参照してください。

8. GUI を手で使う

npm run gui

ブラウザーが自動で開かない場合は、起動ログのローカル URL を使います。editor-core/app/index.html をダブルクリックして開く方法は使いません。ターミナルはサーバーとして動いているので開いたままにします。

  1. 左側の「1 · パックを読み込む」で ZIP/MCPACK を選びます。練習には生成済みの outputs/manual-demo.mcpack を使えます。
  2. 「JSON UIファイル」で ui/manual_demo.json、その下の UI 定義で screen を選び、「選択したUIをプレビュー」を押します。
  3. 配置だけを見るときはプレビューを使います。変更するときは「編集モード」へ切り替え、対象要素と影響範囲を確認します。自動配置、動的 offset、アニメーション中の位置などはドラッグできない場合があり、原文で編集します。
  4. キャンバスの未確定変更は「JSON UIに確定」で確定します。原文欄の変更は「検証して反映」で反映します。確定・適用に失敗した変更を、保存済みと判断しないでください。
  5. 「書き出し」タブに現在の UI を追加し、依存を検査してパックを保存します。ページ再読込で読込みパックと編集内容が失われるため、必要な成果物は先に書き出してください。
  6. 問題がある場合は「ログ・診断」または診断の一括保存を使います。終了は起動ターミナルで Ctrl+C です。

GUI は実験機能です。マウスで編集した後は、書き出したパックを 別の CLI セッションへ取り込み、validate と指定時刻の厳格 PNG で再確認する手順を推奨します。GUI の状態を CLI セッションへ自動共有する機能はありません。

9. Node API：同じ UI の状態を変える

次は実行できる付属プログラムです。先に 4 節でパックを生成し、PNG 依存を導入してください。

node docs/release/manual/examples/sdk-demo.mjs

新しい outputs/sdk-demo に before.png、after.png、result.json ができます。スイッチを 1 回操作した状態を次の描画へ渡すため、after.png には右の紫色の詳細が現れます。インスタンスは finally で閉じます。出力フォルダーが既にある場合は、別名を指定します。

node docs/release/manual/examples/sdk-demo.mjs outputs/manual-demo.mcpack outputs/sdk-demo-2

この例は createRenderer() → import() → render() → interact() → render() → resolveSound() の順に使います。interact() は、渡したローカルトグル状態を返す方式です。毎回 uiInstanceId、最新の localToggleState、その revision を引き継ぎます。サーバー自身が最新状態を保存する方式ではありません。

audioIntent は音声再生の 要求の記述で、resolveSound() は登録 OGG の参照先・ハッシュ・事前検査を返します。この Node/CLI/HTTP の例からスピーカーの音は出ません。 GUI のプレーヤーとは別です。任意のゲーム命令の実行やフォーム送信は行いません。入力・音声の対応範囲は 仕様書 を参照してください。

10. HTTP API：PowerShell から呼び出す

最初のターミナルで次を実行し、起動したままにします。

node local-node/api-server.mjs --connection-file outputs/http-connection.json

別の PowerShell を同じプロジェクトフォルダーで開き、次を実行します。接続ファイルのトークンを表示したり、Git・共有ファイル・相談用ログへ貼り付けたりしないでください。

$connection = Get-Content outputs/http-connection.json -Raw | ConvertFrom-Json
$headers = @{ Authorization = "Bearer $($connection.token)" }
$importBody = @{ pack = (Resolve-Path outputs/manual-demo.mcpack).Path } | ConvertTo-Json
$importResult = Invoke-RestMethod -Method Post -Uri "$($connection.base_url)/api/renderer/v1/import" -Headers $headers -ContentType "application/json; charset=utf-8" -Body ([Text.Encoding]::UTF8.GetBytes($importBody))
$renderBody = @{
  file = "ui/manual_demo.json"
  definition = "manual.screen"
  format = "json"
  frame = 0
  width = 640
  height = 360
  uiScale = 2
  strictSemantics = $true
} | ConvertTo-Json -Depth 30
$renderResult = Invoke-RestMethod -Method Post -Uri "$($connection.base_url)/api/renderer/v1/render" -Headers $headers -ContentType "application/json; charset=utf-8" -Body ([Text.Encoding]::UTF8.GetBytes($renderBody))
$renderResult.result.quality

接続はループバックの 127.0.0.1 に限定され、通常のブラウザーの Origin 付き要求を受け付けません。他の PC やスマートフォンへ公開するサーバーではありません。CLI の保存セッションとは別のメモリ内作業領域です。終了はサーバー側ターミナルの Ctrl+C です。PNG の base64 保存等は HTTP 詳細 と 仕様書 を参照してください。

11. よくある問題と次に確認する場所

症状・コード 次にすること
npm start で画面が開かない 正常です。GUI を使う場合は npm run gui
RASTER_BACKEND_UNAVAILABLE プロジェクトのルートで npm ci --ignore-scripts。対応 OS/CPU の任意依存が導入されたか確認
フォントやテクスチャの未解決 必要な権利のある参照パックを追加。文字のない本書の例と比較
CLI_DEFINITION_AMBIGUOUS definitions の完全な rawKey を指定。先頭候補を推測しない
POCKET_PREVIEW_BLOCKED Pocket の描画は非対応。Classic の定義を選び直す
CLI_SOURCE_CHANGED 読込み時と元パックの内容が異なる。元ファイルを戻すか、別セッションへ新規取込み
CLI_SESSION_LOCKED 同じセッションの別処理が終わるまで待つ。起動中のロックを削除しない
API_REIMPORT_REQUIRED Worker 復旧後に必要なパックを明示して再取込み
画像は出るが実機と違う 対応範囲・状態・時刻・倍率・素材の診断を確認し、実機で別に検証

診断は node local-node/cli.mjs diagnostics --out outputs/diagnostics.json --session outputs/manual-session.json で保存できます。単独実行は 今回の起動の診断で、過去に終了した処理のイベントまで復元するものではありません。連続操作の診断をまとめるときは CLI の workflow を使います。

English · 日本語説明書 · 制限・注意事項

本書は配布版 0.16.1 の公開入出力と実装境界を定義します。0.16.1 は 0.16.0 の実行処理を維持したドキュメント・ライセンス整備版です。将来の機能案は現在の仕様に含めません。各種 passed は、その検査の対象範囲で確認できたという意味です。

1. 対象と入口

対象は Minecraft Bedrock の Classic JSON UI です。パックを読み込み、定義を選択し、明示した状態でレイアウト・描画・診断を計算します。Minecraft 本体、Behavior Pack、Script API、screen controller は実行しません。

Pocket JSON UI は一覧・原文参照・編集の対象にできますが、プレビューは禁止します。OreUI、DDUI、スマートフォン向け Pocket/touch UI の再現は対象外です。Classic という描画プロファイルへの対応を、スマートフォン上での利用対応と読み替えないでください。

入口 状態 実行・状態の寿命
CLI local-node/cli.mjs / npm start 既定 1 回の起動で専用 loopback server/Worker を所有。終了時に停止。状態・原文編集はセッション JSON に保存
Node SDK local-node/api.mjs 対応 createRenderer() で server/Worker を作成し、import() または close() までパックを保持
HTTP local-node/api-server.mjs / npm run api 対応 認証付きの常駐 loopback API。内部で 1 個の SDK renderer を共有
ブラウザー GUI npm run gui 実験機能 明示起動。編集・ポインター操作・ブラウザー音声等の UI アダプターを持つが、ネイティブ実行の証明にはしない

Node.js は 22.14.0 以降、公開モジュールは ESM です。PNG には任意依存 @napi-rs/canvas 0.1.100 と必要なパック素材が必要です。SDK import 自体はブラウザーや subprocess を起動せず、ファイルを編集・保存しません。

2. パックと定義の入力

入力はローカルの ZIP、MCPACK、MCADDON です。MCADDON から選択した Resource Pack を読み込み、Behavior Pack を実行しません。複数 RP があれば RP の manifest UUID を指定します。任意 URL のダウンロード、ディレクトリの直接読込み、ゲームからの状態取得は公開 SDK の import 入力にありません。

スタックは vanilla と imported の最大 2 層です。同じ定義・素材の優先順位は imported が上です。パック内の UI 定義、グローバル変数、参照・素材をカタログ化してから、選択した定義を投影します。file は ui/example.json のような パック内パス、pack は OS 上の 入力アーカイブパスです。

selector 型・制約 使用箇所
file 空でない文字列、最大 1,024 文字、制御文字なし definitions / validate / render / interact
definition 同上。id / rawKey / localName / qualifiedName のいずれかへの一致 同上
kind imported または vanilla list / definitions / validate / render / interact

definitions() は一覧取得であり、絞込み結果が 0 件・複数件でも count / items を返します。次の画面選択規則は validate / render / interact に適用します。候補がちょうど 1 個なら selector の一部を省略できます。複数候補は CLI_DEFINITION_AMBIGUOUS、候補なしは UI_DEFINITION_NOT_FOUND です。名前の雰囲気で画面を選びません。kind がなければ同一ファイル・同一 qualifiedName の上位層を優先します。state 内の推奨定義は診断用であり、任意の定義を自動追加しません。

3. Node SDK の共通契約

import { createRenderer, JsonUiApiError } from './local-node/api.mjs';
const renderer = await createRenderer({ language: 'ja' });
try {
  await renderer.import({ pack: 'C:\\packs\\example.mcpack' });
  const result = await renderer.render({
    file: 'ui/example.json', definition: 'example.screen',
    format: 'json', frame: 0, strictSemantics: true,
  });
  console.log(result.quality);
} finally {
  await renderer.close();
}

全メソッドは Promise を返します。close() 以外の第二引数は任意の { signal: AbortSignal } です。createRenderer() に渡した signal は初期化のみ、各処理はその処理用の signal を渡します。close() に要求・signal を渡す契約はありません。

要求は通常の JSON 相当オブジェクトです。unknown field、undefined、関数、非有限数、循環参照、getter、symbol key、疎配列、独自配列プロパティ、通常オブジェクトでないインスタンス、__proto__ / prototype / constructor key を拒否します。要求は受付時にコピーされ、受付後に元オブジェクトを変更しても処理内容は変わりません。

公開メソッド 受理する第一引数のフィールド（列挙以外は拒否）
createRenderer() settings, language
import() pack, vanilla, resourcePack
list() kind
definitions() file, definition, kind
status() なし / {}
validate() selector + settings, state, strictSemantics
render() selector + settings, state, format, width, height, uiScale, fps, frame, allowPartial, strictSemantics, strictAnimation, drawEvidence, frameSummary, uiInstanceId, localToggleState
interact() selector + settings, state, width, height, uiScale, fps, frame, uiInstanceId, localToggleState, expectedRevision, nodeId, event, inputSource
resolveSound() soundId, selectionSeed, contextSampleRate
close() なし

strictAnimation は render 専用です。interact は内部で意味論の厳格検査を要求するため strictSemantics field 自体を受理しません。resolveSound() に任意のファイルパス、settings、音声バイト列を渡す契約はありません。

作成・読込み・一覧

language は ja / en、既定 ja。settings は次節の設定です。import は pack / vanilla の少なくとも一方が必須で、SDK では OS の絶対パス文字列、最大 32,768 文字を指定します。resourcePack は pack と併用する RP の UUID です。

SDK の import はスタック全体を交換します。 import({pack}) は以前の vanilla を引き継ぎません。両方が必要なら毎回両方を指定します。これに対し CLI import は指定した層だけを交換し、指定しない層を保持します。

成功結果の schema は jsonui-api-import-v1 / jsonui-api-list-v1 / jsonui-api-definitions-v1 / jsonui-api-status-v1 です。import は sources（kind/name/size_bytes/checksum_sha256、必要なら resource_pack_uuid）、file_count、definition_count、diagnostics を返します。一覧は count / items / diagnostics。status はパック読込み、処理待ち数、Worker 情報、機能、PNG backend の availability を返します。status の pending は実行中の status 要求自体も含みます。

4. 設定と CLI の対応

createRenderer({settings}) はインスタンスの既定値です。validate/render/interact の settings はその呼出しだけにマージします。後続要求に保存しません。CLI settings --file はセッションにマージ保存します。トップレベルの幅・高さ等の要求値は、対応する settings 値に優先します。

settings の数値チェックでは数値文字列も数値化します。一方、SDK のトップレベル width / height / fps / frame 等は JSON number が必要です。未知の settings key を受理しません。各 runtime map が 1 MiB 以下でも、組合せたフレーム状態の 1 MiB 上限を別途満たす必要があります。

uiScale: 'auto' は RP の build-info.json の校正値、または Classic 既定 4 倍を使います。width/height は物理出力サイズ、logical_width/logical_height は倍率適用前の canvas サイズです。スマートフォンの GUI scale/touch レイアウトを検出する機能ではありません。

5. 型付き state

state はプレビュー用 JSON です。ゲーム内状態ではありません。正規化は全体を検査し、不正入力を途中まで適用しません。トップレベルで受理する key は次のとおりです。

mockData, collectionData, furnace, brewing, trade, form, messageContext, inventory, slots, anvil, enchanting, horse, book, font_profile, eventFactorySelections。

命名が異なります。 state の raw 値は mockData / collectionData、settings の raw 値は mock_data / collections です。state を指定すると既定 runtime 値を置換し、variables/scroll/local state を初期化します。同じ要求の settings に mock_data, collections, variables, scroll, event_factory_selections, local_toggle_state があれば空でも API_STATE_CONFLICT です。サイズ・言語等の非 runtime 設定は併用できます。

state と明示 uiInstanceId / localToggleState の併用は可能です。型付き state の正規化後にその local state を適用します。明示 field と settings 内の ui_instance_id / local_toggle_state を同時指定すると競合です。

state branch 入力の構造・範囲
mockData binding 値の object。__collections は禁止し collectionData を使う
collectionData collection 名 → row object の配列。row 内の __collections は nested collection
inventory main 最大 27、hotbar 9、armor 4、offhand 1、container containerSize 件。containerSize は 1～256、既定 27

item の受理 key は id, count, name, texture, atlasKey, variant, selected。count は整数 0～999（既定 1）、selected は boolean。texture は安全な textures/... パック相対参照。texture と atlasKey は排他、variant は atlasKey と併用する整数 0～4,095。未知 ID を任意の既存アイテムに置換せず診断します。空スロットを受理する branch では null または省略末尾を空行に正規化します。表示できるアイテムを入力できることは、実機の投入許可・レシピ処理の証明ではありません。

共通上限は UTF-8 JSON 1 MiB、深さ 24、20,000 要素、単一 string 65,536 文字、各 collection 256 rows、各 map 128 collections、nested を含む全体 2,048 rows です。raw mockData / collectionData は型付き branch による生成値の後に適用するため、同じ key を明示上書きできます。

6. validate / render と出力形式

validate は投影後の UI model を検査します。render はさらにフレームを評価します。validate は collection の実行時行・表示入力 binding・資産描画を評価しません。静的な記録済み非対応プロパティは validate でも診断します。

render field 既定・制約
format json、svg、png。既定 json
width, height settings に従う。JSON number の整数 1～16,384
uiScale settings に従う。auto / 整数 1～8
fps settings に従う。有限 number 1～240
frame 0 始まり整数。API 受付上限 864,000、さらに pipeline 上限 fps×3,600。JSON/SVG は既定 0、PNG は既定 round(fps)
strictSemantics boolean、既定 false。意味論・評価・行参照・表示入力 binding・記録済み非対応プロパティの非 passed で停止
strictAnimation boolean、既定 false。animation quality の非 passed で停止
allowPartial boolean、既定 false、PNG 専用。調査用の不完全 PNG を許可。strict 判定に優先しない
drawEvidence boolean、既定 false、PNG 専用。最終描画入力を上限付きで追加
frameSummary boolean、既定 false。JSON 専用、strictAnimation と併用不可。件数・打切り情報のみ、renderable:false
uiInstanceId local state の instance ID。省略時 settings 値
localToggleState 明示する場合 uiInstanceId が必須

時刻は frame/fps 秒であり、PNG 既定は入口アニメーション開始約 1 秒後です。開始瞬間には frame:0 を明示します。API の fps に小数を指定できても frame 自体は整数です。

形式 SDK 結果と意味 CLI / HTTP
JSON schema:'jsonui-api-render-v1', ok:true, format:'json'。viewport、time、selected、投影 document、validation、frame IR、quality、stage_diagnostics を含む。描画 pixels は含まない CLI は stdout または .json。HTTP は result 内の object
SVG 同じ render schema、format:'svg'、svg:string と metadata。実レイアウトの矩形境界図。テクスチャ・glyph・3D の完成画像ではない CLI は --out .svg 必須。HTTP result.svg は string
PNG 同じ render schema、format:'png'、png:Buffer と metadata。素材・フォントの測定後に再配置し最終画面を描画 CLI は --out .png 必須。HTTP は下記 base64 object

PNG metadata は complete, preview_complete, draft, diagnostics, native_equivalence, provenance, final_frame_summary、animation/binding/collection quality を含みます。final_frame_summary は実資産測定後の件数・frame/hash・box digest・再配置回数の有界情報です。全 frame の sidecar ではありません。JSON の座標は測定前、PNG の最終座標は測定後です。

8. interact と local state

interact は 呼出し側が状態を保管する stateless projection です。server に最新の UI session を保存せず、毎回指定された定義・state・local state を投影して入力を評価します。必要な field は uiInstanceId/nodeId/expectedRevision と、候補を一意にする selector です。

field 仕様
uiInstanceId 空でない安全な ID、最大 256 文字
nodeId 現在の JSON frame に実在する node ID、最大 1,024 文字。caption や配列 index ではない
expectedRevision 非負 safe integer。渡した local state の revision と一致する必要あり
localToggleState 任意。省略時はその UI の初期状態を評価
event activate / escape、既定 activate
inputSource mouse / keyboard。既定は activate→mouse、escape→keyboard

local state の形式:

{
  "version": 1,
  "instanceId": "inspection-1",
  "revision": 0,
  "values": { "current-node-id": false }
}

values は現在の UI の writable local toggle ID → boolean、最大 20,000 件。現在の全 local ID は JSON render の frame.bindings.localToggleState から取得します。外部 binding が所有する toggle は local state で上書きできません。radio は同じ親の明示 group に限って排他選択を扱います。

入力 mapping は mouse activate に対する button.menu_select の pressed と、keyboard escape に対する menu_cancel/menu_exit の global を確認します。input_mode_condition は省略または not_gamepad だけを扱い、touch/gamepad/gaze を推測しません。複数 action の実行順が不明なら実行しません。hidden/disabled/ignored/描画外の対象は blocked、未知 action は unsupported と診断します。

結果は schema:'jsonui-api-interaction-v1', ok:true、execution:'stateless_preview_projection'、selected/node_id/ui_instance_id/previous_revision、projection/form_descriptor の SHA-256、interaction/status/effects/diagnostics、localToggleState、audioIntent、quality、stage_diagnostics、effects_executed、playback/native_equivalence です。blocked/unsupported は API 処理成功の結果として返る場合があるため、ok だけで操作成功としません。

適用する effect は localTogglePatch だけです。正常適用ごとに revision が 1 増えます。mockPatch/collectionPatch/close/navigate/chooseNavigate/clipboard 等は有限アダプターの記述であり、SDK は実行しません。フォーム応答の送信、フォームの閉開、BP への保存もありません。返された local state を次の interact/render に渡すことで同じ UI instance の見え方を変更できます。

別 instance、revision 不一致、未知/readonly ID を拒否します。ただし 古い snapshot と一致する古い expectedRevision を一緒に渡す再評価は可能です。これはサーバー保存式の完全な stale 操作防止ではありません。複数クライアントの最新性・排他は利用側が実装します。

音声 intent は mouse activate の有効な対象に限定します。keyboard/escape は発音要求にしません。未解決 sound_name/volume/pitch binding、capture 不完全、無効・非表示状態から古い値を使った要求を生成しません。soundName/soundVolume/soundPitch/originScreenId/interactionId は要求の記述です。音声要求と action の対応可否は独立しているため、未知 action が unsupported でも有効な sound_name があれば intent を返す場合があります。intent は音源解決・再生完了の結果ではありません。

9. resolveSound と音声

soundId は登録された sounds/sound_definitions.json の ID（最大 256 文字、制御文字・$/# 禁止）。selectionSeed は任意 string 最大 256、既定空。contextSampleRate は整数 8,000～192,000、既定 48,000 です。

解決順は上位の imported 定義、その ID がなければ vanilla 定義です。音声ファイルは別に imported → vanilla の順で探索します。上位層に参照先の候補ファイルがない場合は、下位層の同じ参照先を探します。上位層にあるファイルの形式競合・曖昧さ・非対応形式・事前検査失敗は、下位音源への切替で回避しません。定義とファイルの所有層が異なる場合があり、結果には両方を記録します。拡張子明示はその形式、拡張子なしは同じ stem の OGG/WAV が一意なときだけ解決します。

対応は短い Ogg Vorbis と WAV PCM16。音源最大 4 MiB、10 秒、mono/stereo、8,000～192,000 Hz、PCM 予約上限 8 MiB。定義最大 8 MiB、50,000 sound IDs、1 定義 64 候補。stream:true、FSB、MP3、Opus、chained OGG 等は非対応です。候補 pitch は 0.5～2、volume は非負有限数、weight は整数 1～1,000,000。definition 直下 volume/pitch はこの resolver では非対応です。

複数候補は soundId と selectionSeed の SHA-256 による安定した weight 選択 sha256-weighted-v1 です。Bedrock の乱数選択との一致を主張しません。OGG は header/page/CRC/sequence/packet/EOS/長さ/PCM 予約を事前検査します。完全な Vorbis decoder ではなく、ネイティブ decoder のメモリをハード上限で拘束するものでもありません。

結果は schema:'jsonui-api-sound-v1', ok:true、sound object（jsonui-sound-v2）と playback:'not_executed' / native_equivalence:'not_evaluated'。sound には定義・ファイルのパック/パス、codec/container、channels/sampleRate/duration、encodedBytes、contentRevision（ファイル SHA-256）、候補/index/選択 policy、音量/pitch/category/is3D、warnings 等を返します。音声バイト列は返さず、SDK/HTTP/CLI はスピーカー再生しません。

GUI の音声 player は別途 browser decode/play を試みます。category 別ゲーム mixer・position/distance は適用せず warning を残します。audibleVerified/nativeVerified/gameMixerVerified は false。形式検査・復号成功だけで聞こえたことを認定しません。

createRendererServer({port?,signal?}) は local-node/api-server.mjs の公開 factory。port は整数 0～65,535、既定 0（自動割当）、bind は 127.0.0.1 固定。返す connection は schema/base_url/token/pid、close は冪等な終了 Promise です。JSON 要求に signal を埋め込みません。

POST /api/renderer/v1/list SDK list object / {}

成功は {schema:'jsonui-renderer-http-v1',ok:true,correlation_id,result}、失敗は同じ schema の ok:false/error、非 2xx status。error は code/message/category/retryable/correlation_id/details/context。SDK は result を二重に包みません。

PNG の result.png は {encoding:'base64',media_type:'image/png',size_bytes,checksum_sha256,data}。SVG は result.svg の string。HTTP に保存先を渡す API はありません。8 同時要求、32 接続、要求 JSON 16 MiB、応答 JSON 64 MiB、本文受信 30 秒。base64 で容量が増えるため大きな PNG は HTTP 応答上限で失敗し得ます。応答は no-store / nosniff、要求 ID header、Connection:close を付けます。

代表 status は未認証 401、Host/Origin 拒否 403、route 不明 404、method 違い 405、content type 415、容量 413、過負荷 429、本文 timeout 408、処理 timeout 504、cancel 499。全 code の固定分類表ではなく、実応答 code/context を確認します。

CLI server 起動の connection-file は新規作成専用。停止後も descriptor を残し、token は server 停止とともに失効します。file の存在を server 生存の証明としません。再起動には別パスか、停止済みの自分の旧 descriptor を確認して削除します。Unix mode 0600 が Windows ACL を完全制御するという保証はありません。

12. 内部処理と描画対象

  1. archive のサイズ・entry・path・CRC 等を検査し、処理用の登録を作成。
  2. UI/変数/素材の catalog を構築、上位層と一意な定義を選択。
  3. 継承、controls、変数/default/conditional、対応 modifications、明示 factory branch を投影し、原文由来と依存診断を保持。
  4. model validation と記録済み native property 検査を実施。
  5. 明示 mock/collection/local state と animation の絶対時刻を評価し、layout boxes/frame IR を生成。
  6. JSON は IR、SVG はその境界図。PNG はパック素材/localization/font を取得・測定して必要な再配置後に raster 描画。
  7. 最終 quality/diagnostics/digest を返却。ファイル保存・session 更新は CLI/呼出し側の別責務。

通常 palette は screen/panel/collection_panel/label/button/dropdown/image/input_panel/stack_panel/grid/scroll_view/edit_box/toggle/scroll_track/scrollbar_box。custom/factory/tooltip_trigger は保持・認識しても、全 runtime を一般描画できるという意味ではありません。未知 field は model に保持しますが、未対応描画機能の忠実な再現は保証しません。JSONC を parse した model は comment を保持しないため、投影・生成結果を原本と byte 同一とは扱いません。

binding は公開 JSON UI の global/collection/view 等の対応部分と明示状態を評価します。ゲームの不透明な renderer data、Molang 全体、controller による値の生成は実行しません。collection_index は直近の collection owner と行 context を確認し、panel だけを挟んだ場合にも任意の祖先へ飛ばして正当化しません。

画像は対応するパック内 PNG/JPEG 等の resource と texture sidecar、UV・nine-slice 等の対応 drawing contract を使います。実フォントが足りなければ厳格 PNG を停止し、OS フォントで不足を黙って補いません。bitmap profile と observed-smooth profile は明示選択し、後者は観測近似です。公開配布版に proprietary な Minecraft font/texture/model 一式は含めません。

native renderer は限定された item/progress/モデル等の安全な surrogate を持ちます。player/horse/book 等の資産に基づく 3D 表示は deterministic な orthographic snapshot であり、Bedrock の shader/lighting/Molang/render pipeline 全体ではありません。geometry/texture の不足・未知機能・上限超過を検出します。

animation は alpha/offset/size/uv/color/wait/flip_book の対応部分、有限な next chain、絶対時刻 sample を計算します。easing は linear と in/out/in_out の quad/cubic/quart/quint/sine/expo/circ/back/elastic/bounce。定義/track 最大各 2,048、chain 64、定義総量 2 MiB。イベント副作用、activation/reset、描画される瞬間の native clock 等は別途非対応診断です。

13. 主要上限とライフサイクル

上限は保証する処理容量ではなく拒否境界です。異なる層の上限が併存し、先に到達した上限で失敗します。これらの値を超える UI が実機で不正という意味でもありません。

対象 現行の主な上限

SDK 受付済み処理 実行中を含む 8 件、1 renderer 内は直列

展開比率 展開後 8 MiB 以上の entry で 200 倍超を読込み拒否。圧縮爆弾対策に使う

SDK/HTTP のパックは無操作 30 分で自動削除しません。import/close まで保持します。通常の worker/cache 上限、容量制限は維持します。Worker が復旧し接続 token/generation が変われば stack を無効化し API_REIMPORT_REQUIRED 等を返します。以前の projection ID を再利用せず import し直します。

取消 signal は受付・待機・処理の各境界で検査します。待機要求は prompt に拒否されても、予約された queue slot は直列 task がそこへ到達してから解放します。同期処理・OS 操作を即座に停止できる保証ではありません。close は新規受付を止め、所有処理を cancel、server/Worker と queue の終了を待ちます。複数 close は同じ Promise にまとまります。

import 失敗時は新規登録を片付け、通常は旧 stack を保持します。cleanup が失敗して登録を安全に追跡できなければ renderer を閉じ、context に recreate_renderer_required/import_cleanup 等を返します。取消の通知が cleanup 完了より早く返ることがあります。

HTTP の複数 clients は 同じ stack を共有します。一人の import が他の client にも影響します。独立したパックの処理には別 renderer/server を用意します。TCP 接続切断はその要求の取消、server close は全体終了です。

14. ファイル保護・errors・検証根拠

CLI の出力は拡張子/通常 file/path を検査し、元 archive、要求 file、アプリ本体への上書きを拒否します。新規作成が既定、成果物だけ --force で置換。兄弟 temporary file を sync してから final 名を公開し、親 directory の電源断 durability までは保証しません。SDK/HTTP は保存を行わないので、利用者の writeFile は利用者が原本保護・上書き policy を実装します。

SDK は JsonUiApiError を throw し、code/message/category/retryable/correlation_id/details/context を持ちます。内部 error は non-enumerable cause。公開診断は sanitize しますが、入力内の private 情報を無条件に公開共有してよいという意味ではありません。HTTP token と connection descriptor は認証情報です。

0.16.0 の既存検証記録は Node 3,163 success・39 skip、共有 core 533 success、28 状態の strict PNG、39 操作、サンプル OGG 全復号です。これらは 0.16.0 の履歴であり、0.16.1 の新規検査数や Minecraft/browser の実行結果として計上しません。現配布版の文書・package 検査結果はリリース報告を参照してください。

native_equivalence: 'not_evaluated' / native_parity_verified: false Minecraft 実機との一致をこの結果では証明していません。
playback: 'not_executed' 音源や再生要求の情報はありますが、その API は発音していません。

--strict-semantics は選択した投影の参照・評価・collection・表示／入力 binding・記録済みプロパティ等を厳格に検査します。validate はフレーム全体を評価するコマンドではなく、PNG も生成しません。アニメーションまで停止条件に含める場合は、プレビューに --strict-animation を指定してください。

通常の PNG は不足・非対応が残る場合に停止します。--allow-partial は調査用の部分描画を明示的に許可する指定で、実機互換性を高めるものではありません。--strict-semantics と --strict-animation の停止条件を解除する指定にもなりません。

4. 状態・操作・アニメーションの境界

フォーム、変数、コレクション、スクロール位置、時刻などは、呼出し側が与えたプレビュー状態です。ゲームから自動取得した最新状態とは限りません。実機でタイトル・本文・行・ボタン等が変わる場合は、必要な状態を変えて複数のプレビューを検査してください。

interact() は、フォームの記述と uiInstanceId を保ちながら、対応するローカルトグル状態を更新できます。ゲーム内でフォームを開閉しないまま入力が成功する証明ではありません。返された localToggleState を次の要求へ渡す必要があります。外部 binding が所有する状態をローカル保存状態で上書きしたり、別の UI の保存状態を混ぜたりしないでください。

expectedRevision は要求で渡した状態の番号との整合性を検査します。サーバーが最新状態を保管する方式ではないため、古い状態と古い番号を組にして再送することはできます。最新状態の保管や複数利用者の競合処理は呼出し側の役割です。

操作 API が実行する効果は localTogglePatch だけです。navigation、フォーム送信、clipboard 等の効果が記述されても、API が実行したとは扱わないでください。ドラッグやキーを連続再生してゲームの入力ループを再現する機能でもありません。GUI には個別の操作経路がありますが、API の効果記述と同一の実行範囲とは限りません。

アニメーションは、指定された時刻・イベント条件でのサンプルです。実機での画面生成、ネイティブ時計、イベントの順序、副作用、入力遅延、サーバーとの同期は未検証です。uv / size / offset に looping を持つ記録済みの組合せや、一部の flip_book 接続には互換性診断が残ります。数値を計算できても、この診断が消えるわけではありません。

5. OGG・WAV と発音の制限

登録済みサウンド ID を、読み込んだパックの音源へ解決します。resolveSound() は任意の OS ファイルを読む API ではなく、音声バイト列の返却やスピーカー再生も行いません。

対応する短音は OGG Vorbis または PCM16 WAV、1 / 2 チャンネル、8,000～192,000 Hz、10 秒以内です。さらに音源ファイル 4 MiB、復号後 PCM の予約量 8 MiB 等の制限があります。10 秒以内でも、予約量・パケット数・構造・その他の制限によって拒否される場合があります。

Opus、FSB、連結 OGG、長音のストリーム再生には対応しません。拡張子を .ogg に変えるだけでは Vorbis になりません。同じ音源名の OGG と WAV が曖昧になる場合は、サウンド定義で拡張子を明示してください。

GUI のブラウザー再生は、カテゴリ別の Minecraft 音量スライダーや 3D 位置音響を再現しません。該当する定義では AUDIO_PREVIEW_CATEGORY_MIXER_NOT_APPLIED / AUDIO_PREVIEW_POSITIONAL_NOT_APPLIED を報告します。候補の重み付き選択も、ゲームの乱数列と完全一致するとは限りません。合成 pitch の対応範囲は 0.5～2、出力 gain は 1 以下に制限され、GUI には別のプレビュー音量があります。

ブラウザーの音声許可、音声 OFF、音量 0、音源の準備時間、復号失敗、同時再生数・メモリ等で発音されないことがあります。音源の参照や形式検査に成功したこと、Web Audio に再生開始を要求できたことは、スピーカーから音が聞こえた証拠ではありません。この版ではブラウザー実音・実機実音の確認はしていません。

6. 画像・フォント・アイテム・3D モデル

公開ソースには Minecraft / Mojang のテクスチャ、フォント、音声、スキン、モデル、完全な UI を同梱しません。必要な継承元と素材は、対象のゲーム版に合い、利用権を持つ参照パックから読み込んでください。パックの優先順位、内容、文字言語、UI 倍率、描画寸法が変われば、結果も変わり得ます。

素材や必要な入力が欠けている場合は診断を返します。厳格 PNG は、足りない素材を無関係な画像で補って完成したと扱う機能ではありません。JSON / SVG の配置だけが得られても、PNG の最終文字測定・再配置や、ゲームの字体・レイヤー順と同じになるとは限りません。

アイテムの数値 ID 表は対象版に依存します。独自アイテム、補助データ、NBT、染色、エンチャント、動的な表示等の全状態には対応していません。モデルが必要な品目で NATIVE_ITEM_MODEL_REQUIRED が出たら、面テクスチャを完成アイコンと読み替えないでください。

対応する player / horse 等のモデル経路があっても、全エンティティのゲーム描画機構ではありません。player は参照パックのモデル・スキンを使い、利用者のアカウントスキンを自動取得しません。実装したカメラ・材質・controller・状態の範囲外は、診断または未対応として扱います。

7. 診断は限定された互換性検査

8. 大きな UI・編集・出力の注意

ノード数、生成数、入れ子、描画矩形、画像メモリ、要求時間、応答量等に制限があります。主要な例はモデル 50,000 ノード、PNG 5,000 矩形、PNG 一辺 8,192 px・総画素 16 Mi ピクセル、フレーム応答 24 MiB です。これはレンダラーの予算であり、Minecraft の UI 上限や FPS の保証ではありません。上限の全一覧と適用箇所は仕様書を参照してください。

--frame-summary は大きなフレームの概要を JSON で受け取るための指定です。完全な診断本文・描画可能なフレーム・PNG を返さず、生成や評価の上限も解除しません。画面を分割して検査する場合は、部分ごとの成功を全画面の合格に置き換えないでください。

実験版 GUI の編集では、同じ共有定義を使う複数の要素が影響を受ける場合があります。生成セルには独立した原文がない場合もあります。移動・削除・継承解除を常に任意の一要素だけへ適用できるわけではありません。草稿の確認、原文への確定、エクスポートを区別してください。

原文の undo / redo は無制限ではなく、プレビューのクリック状態、設定変更、UI 選択をすべて戻す機能でもありません。CLI の原文履歴は最大 64 件 / 8 MiB で、セッション全体にも上限があります。履歴が削除された場合や大きすぎる単一編集では取り消せないことがあります。

元アーカイブを変更せず、別の出力へ保存する設計です。ただし、書き出したファイルが意図した内容かは、原文・診断・再読込みで確認してください。出力先の上書き保護を回避して入力と同じ場所へ保存する使い方はしないでください。
