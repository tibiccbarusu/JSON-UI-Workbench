JSON UI Workbench 0.16.1 — User guide

日本語 · Technical specification · Limitations · License

This application reads Classic JSON UI from Minecraft Bedrock resource packs so you can inspect its appearance and representative states outside the game. It does not start Minecraft or execute an add-on's JavaScript. Start with the small included example to learn the sequence: import, select a screen, preview, edit, and export.

Preview support is limited to Classic UI. Pocket UI, including the touch-oriented UI commonly used on smartphones, cannot be previewed. This distribution runs on a PC with Node.js; it is not a smartphone application. A device type and Minecraft's UI profile are separate conditions. See Limitations for the precise scope.

1. Choose an entry point

Method Entry point Suitable work
Type commands in a terminal CLI; the default in this guide Validation, images, source editing, pack export
Call repeatedly from a program Node API Repeated rendering of one pack; AI integration
Send HTTP requests from Python or another language HTTP API Requests to a persistent local service
Inspect and edit with a mouse Experimental GUI Manual inspection and editing; review the unfinished features' results

npm start prints CLI guidance and exits. Use npm run gui to open the browser interface. The existing start.bat is also a compatibility entry for the GUI. CLI and API calls do not automatically open a browser.

2. Install and prepare

  1. Extract the entire distribution ZIP. Do not run files directly inside the ZIP. For example, use C:\Tools\jsonui-workbench-0.16.1.
  2. Obtain a compatible Node.js 22.14.0 or later, with npm, from the official Node.js website. The baseline validation environment is Node.js 22.14.0.
  3. On Windows, open the extracted folder in File Explorer, type powershell in the address bar, and press Enter. The terminal now starts with this folder as its working directory.
  4. Run these commands one at a time.
node --version
npm --version
npm ci --ignore-scripts
node local-node/cli.mjs help

npm ci installs the dependencies recorded in the included package-lock.json. --ignore-scripts disables dependency installation scripts. Initial package downloads require a network connection. npm ci replaces an existing node_modules directory, so run it in this application, not an unrelated project. JSON and SVG inspection are distinct from PNG rendering: PNG requires the optional @napi-rs/canvas dependency.

If Windows refuses npm.ps1 under its execution policy, use npm.cmd, for example npm.cmd ci --ignore-scripts or npm.cmd run gui in the same folder. No execution-policy change is needed.

If Windows says node is not recognized, reopen the terminal after installation and check node --version. If start.bat has installed the application's private Node executable, use .\.jsonui\runtime\node.exe instead of node. Running the GUI launcher alone does not establish that npm and the PNG dependency have been installed.

On macOS/Linux, open a terminal, cd to the extracted directory, and use the same node and npm commands. The / separators in the commands below work in PowerShell and POSIX shells. Windows-specific commands such as Get-Content and Invoke-RestMethod are not POSIX shell commands.

3. Understand paths and names

Example Meaning
outputs/manual-demo.mcpack An input pack on your PC. Ordinary relative paths are based on the current working directory
outputs/manual-session.json The CLI working record: source paths and hashes, settings, and source edits
ui/manual_demo.json A UI file inside the pack; it need not exist as a separate PC file
manual.screen A UI definition: namespace manual combined with definition screen
/screen/controls/2/card A JSON Pointer identifying a location in the authored JSON

Quote paths containing spaces, for example "C:\My Packs\sample.mcpack". Use the same --session file throughout one task. Without it, the CLI uses .jsonui-cli/session.json in the current working directory.

4. Produce your first preview with the included example

The tutorial uses original JSON, a white 1-pixel image, and an included synthetic OGG sound. It needs no Minecraft image or font. Its small screen contains no text, making it useful for checking PNG setup. It is a renderer tutorial, not a complete add-on that opens an in-game form.

node docs/release/manual/examples/build-demo.mjs
node local-node/cli.mjs import --pack outputs/manual-demo.mcpack --session outputs/manual-session.json
node local-node/cli.mjs list --session outputs/manual-session.json
node local-node/cli.mjs definitions --file ui/manual_demo.json --session outputs/manual-session.json
node local-node/cli.mjs settings --file docs/release/manual/examples/settings-demo.json --session outputs/manual-session.json

build-demo.mjs creates a new outputs/manual-demo.mcpack. It stops if that file already exists and does not overwrite it. To repeat the exercise, choose a different name.

node docs/release/manual/examples/build-demo.mjs outputs/manual-demo-2.mcpack

After confirming ui/manual_demo.json and manual.screen in the listings, run:

node local-node/cli.mjs validate --file ui/manual_demo.json --definition manual.screen --strict-semantics --session outputs/manual-session.json
node local-node/cli.mjs preview --file ui/manual_demo.json --definition manual.screen --frame 0 --format json --strict-semantics --out outputs/manual-frame.json --session outputs/manual-session.json
node local-node/cli.mjs preview --file ui/manual_demo.json --definition manual.screen --frame 0 --format svg --strict-semantics --out outputs/manual-frame.svg --session outputs/manual-session.json
node local-node/cli.mjs preview --file ui/manual_demo.json --definition manual.screen --frame 0 --format png --strict-semantics --out outputs/manual-frame.png --session outputs/manual-session.json

Open outputs/manual-frame.png. It shows a dark background, a horizontal banner, a card on the left, and a switch below it. The detail area on the right stays hidden until the switch is activated. The settings use a 640 × 360 output with UI scale 2. At scale 2, one UI unit corresponds to approximately two output pixels.

Output Purpose
JSON Inspect resolved values, frames, rectangles, bindings, and diagnostics
SVG Inspect element boundaries and placement; it is not a textured or font-rendered image
PNG An image rendered with supported textures, fonts, and other assets

By default, an existing output file stops the command. Add --force only when you intend to replace your own output. Even --force cannot make a source pack or the session file an output destination.

5. Inspect your own packs and states

Follow the same sequence. Change the import input to your ZIP/MCPACK/MCADDON, then use list and definitions to find actual file and definition names. Use --pack for a regular pack and --vanilla for a vanilla reference pack; you may supply both together. You must have the right to use any reference assets.

node local-node/cli.mjs import --pack "C:/MyPacks/addon.mcaddon" --vanilla "C:/MyPacks/reference.zip" --session outputs/my-session.json
node local-node/cli.mjs list --session outputs/my-session.json

When an MCADDON contains multiple resource-pack candidates, use --resource-pack with the header UUID reported by the diagnostic. The renderer does not automatically choose the first candidate. Default PNG output stops if required reference assets or glyphs are missing. Inspect the structure with JSON/SVG, or supply authorized assets before retrying.

Provide representative states for values the renderer cannot obtain from the running game. For example, save this as UTF-8 outputs/state.json:

{
  "form": {
    "type": "action",
    "title": "Sample",
    "body": "Choose an item",
    "buttons": [{ "text": "Continue" }, { "text": "Close" }]
  }
}

node local-node/cli.mjs settings --state-file outputs/state.json --replace-state --session outputs/my-session.json

This is preview data. It does not open a native form or create definitions missing from the imported pack. --replace-state replaces previous representative data and local toggle state. Advanced raw data uses the settings fields mock_data and collections. Check the Technical specification for typed state syntax and input conflicts.

Animation time is frame / fps seconds. --frame 30 --fps 60 selects 0.5 seconds; --frame 0 selects the start. If PNG time is omitted, it uses approximately one second after the start, so specify time explicitly for comparisons. Add --strict-animation to stop when animation quality remains unsupported or uncertain.

6. Read validation results

The CLI normally returns one JSON result. ok: true with exit code 0 means the command succeeded; ok: false with a nonzero code means it failed. PowerShell exposes the code as $LASTEXITCODE immediately after a command. Use help for human-readable guidance and --language en for English console descriptions.

Inspect quality, stage_diagnostics, and diagnostics, even when an image exists. passed means evaluated within the supported scope; unknown means unsupported behavior or incomplete observations remain; failed means a detected inconsistency; not_evaluated means no evaluation. quality.native_properties checks recorded unsupported properties, not the complete Minecraft specification.

--strict-semantics refuses uncertain resolution, collection-row references, visual/input bindings, and related checks for the selected UI. Default PNG output also stops on unresolved assets and other covered conditions. Use --allow-partial only for a deliberately incomplete diagnostic image. Explicit strict gates take precedence: this flag alone does not bypass a strict failure. complete and preview_complete do not certify matching native pixels, interactions, or sound.

7. Edit source, undo, and export

First move the tutorial card 12 UI units to the right.

node local-node/cli.mjs edit --operation docs/release/manual/examples/move-demo.json --session outputs/manual-session.json
node local-node/cli.mjs preview --file ui/manual_demo.json --definition manual.screen --frame 0 --format png --strict-semantics --out outputs/manual-edited.png --session outputs/manual-session.json
node local-node/cli.mjs undo --session outputs/manual-session.json
node local-node/cli.mjs redo --session outputs/manual-session.json

The included move-demo.json sets the offset at /screen/controls/2/card to [36, 56]. Offset is relative to the anchors, not an absolute screen-pixel coordinate. The edit is saved in the session; the input MCPACK remains unchanged.

To edit the whole file in your own editor, extract the authored source:

node local-node/cli.mjs read --file ui/manual_demo.json --out outputs/manual-authored.json --session outputs/manual-session.json

Edit outputs/manual-authored.json, save it as UTF-8, and apply it:

node local-node/cli.mjs edit --file ui/manual_demo.json --text-file outputs/manual-authored.json --session outputs/manual-session.json

Rejected syntax and other rejected changes preserve the last committed edit. A new committed edit clears redo history. Undo has count and size limits; settings changes and UI selection are outside source undo.

Finally inspect dependencies and export a new pack:

node local-node/cli.mjs export --file ui/manual_demo.json --definition manual.screen --plan --out outputs/manual-export-plan.json --session outputs/manual-session.json
node local-node/cli.mjs export --file ui/manual_demo.json --definition manual.screen --out outputs/manual-selected.mcpack --session outputs/manual-session.json

Export includes the selected UI and its required dependencies. It is not a full copy of an add-on's files, BP scripts, world, or player state. Unresolved dependencies stop export. The Technical specification covers the operation contract; the legacy CLI reference in Japanese provides additional pack-metadata and operation-JSON examples.

8. Use the GUI manually

npm run gui

If the browser does not open automatically, use the local URL in the startup log. Do not double-click editor-core/app/index.html as a substitute. Keep the terminal open: it is running the server.

  1. In the left-hand “1 · パックを読み込む” section (load a pack), select a ZIP/MCPACK. You can practice with the generated outputs/manual-demo.mcpack.
  2. Select ui/manual_demo.json under “JSON UIファイル” (JSON UI file), select screen in the definition list below it, and press “選択したUIをプレビュー” (preview selected UI).
  3. Use preview mode to inspect placement. Switch to “編集モード” (edit mode) to change it, and check the target and affected scope. Flow layout, dynamic offsets, and animated positions may prevent dragging; edit the source instead.
  4. Commit pending canvas edits with “JSON UIに確定” (commit to JSON UI). Apply source-field edits with “検証して反映” (validate and apply). A failed commit or apply is not a saved edit.
  5. Add the current UI under the “書き出し” (export) tab, inspect its dependencies, and save a pack. Reloading the page loses the loaded pack and edits, so export anything you need beforehand.
  6. Use “ログ・診断” (logs and diagnostics) or the diagnostic bundle if something fails. Stop the server with Ctrl+C in its terminal.

The GUI is experimental. After visual editing, import its exported pack into a separate CLI session, then check validate and strict PNG at an explicit time. GUI memory is not automatically shared with a CLI session. The labels above are the source-verified Japanese controls; interface translation availability does not change these steps.

9. Node API: change the same UI's state

The included program is runnable. First generate the pack in section 4 and install the PNG dependency.

node docs/release/manual/examples/sdk-demo.mjs

It creates before.png, after.png, and result.json in a new outputs/sdk-demo directory. It activates the switch once and passes the returned state to the next render, making the purple detail area appear on the right in after.png. The renderer closes in finally. Choose another output directory if it already exists:

node docs/release/manual/examples/sdk-demo.mjs outputs/manual-demo.mcpack outputs/sdk-demo-2

The sequence is createRenderer(), import(), render(), interact(), render(), and resolveSound(). interact() returns the updated local toggle state. Carry uiInstanceId, the current localToggleState, and its revision into subsequent requests. The server does not retain the latest interaction state for you.

audioIntent describes a playback request. resolveSound() reports the registered OGG reference, hash, and preflight inspection. This Node/CLI/HTTP example does not produce speaker output. It is separate from the GUI's audio player. It does not execute arbitrary game commands or submit a native form. See the Technical specification for supported input and audio behavior.

10. HTTP API: call it from PowerShell

Run this in the first terminal and leave it running:

node local-node/api-server.mjs --connection-file outputs/http-connection.json

Open another PowerShell in the project folder and run the following. Do not print the token or paste it into Git, shared files, or support logs.

$connection = Get-Content outputs/http-connection.json -Raw | ConvertFrom-Json
$headers = @{ Authorization = "Bearer $($connection.token)" }
$importBody = @{ pack = (Resolve-Path outputs/manual-demo.mcpack).Path } | ConvertTo-Json
$importResult = Invoke-RestMethod -Method Post -Uri "$($connection.base_url)/api/renderer/v1/import" -Headers $headers -ContentType "application/json; charset=utf-8" -Body ([Text.Encoding]::UTF8.GetBytes($importBody))
$renderBody = @{
  file = "ui/manual_demo.json"
  definition = "manual.screen"
  format = "json"
  frame = 0
  width = 640
  height = 360
  uiScale = 2
  strictSemantics = $true
} | ConvertTo-Json -Depth 30
$renderResult = Invoke-RestMethod -Method Post -Uri "$($connection.base_url)/api/renderer/v1/render" -Headers $headers -ContentType "application/json; charset=utf-8" -Body ([Text.Encoding]::UTF8.GetBytes($renderBody))
$renderResult.result.quality

The service binds to loopback 127.0.0.1 and refuses ordinary browser requests carrying an Origin. It is not a server for other PCs or smartphones. Its workspace is in memory, separate from CLI session files. Stop it with Ctrl+C in the server terminal. The entry-point guide contains additional PowerShell examples, and the bilingual Technical specification documents the HTTP contract, including base64 PNG output.

JSON UI Workbench 0.16.1 Technical Specification

日本語 · English user guide · Limitations and notices

This document specifies the public inputs, outputs, and implementation boundaries of release 0.16.1. Version 0.16.1 updates documentation and licensing while preserving the 0.16.0 execution implementation. Proposed future features are outside the current specification. A passed result applies only to the scope of that particular check.

1. Scope and entry points

The target is Minecraft Bedrock Classic JSON UI. The renderer imports packs, selects definitions, and computes layout, rendering, and diagnostics using explicitly supplied state. It does not execute Minecraft, Behavior Packs, Script API, or native screen controllers.

Pocket JSON UI can be listed, read, and edited, but its preview is blocked. OreUI, DDUI, and smartphone Pocket/touch UI reproduction are outside scope. Support for the Classic rendering profile does not imply support for using the tool on a smartphone.

Entry point Status Execution and state lifetime
CLI local-node/cli.mjs / npm start Primary Owns a loopback server/Worker for one invocation; stops them at exit. Settings and authored edits persist in session JSON
Node SDK local-node/api.mjs Supported createRenderer() owns a server/Worker and retains imported packs until another import() or close()
HTTP local-node/api-server.mjs / npm run api Supported Persistent authenticated loopback API backed by one shared SDK renderer
Browser GUI npm run gui Experimental Explicit opt-in. Provides UI adapters for editing, pointer input, and browser audio; these are not evidence of native execution

Node.js 22.14.0 or later is required. Public modules are ESM. PNG requires the optional @napi-rs/canvas 0.1.100 dependency and the necessary pack assets. Importing the SDK module alone starts no browser or subprocess and does not edit or save files.

2. Pack and definition inputs

Inputs are local ZIP, MCPACK, and MCADDON files. The selected Resource Pack in a MCADDON is imported; its Behavior Pack is not executed. When multiple RPs are present, specify the RP manifest UUID. The public SDK does not provide URL downloads, direct directory import, or game-state acquisition.

A stack has at most two layers: vanilla and imported. Imported definitions and assets take precedence when both layers provide the same resource. UI definitions, global variables, references, and assets are cataloged before the selected definition is projected. file is a pack-relative path, such as ui/example.json; pack is the archive path on the operating system.

Selector Type and constraints Used by
file Nonempty string, at most 1,024 characters, no control characters definitions / validate / render / interact
definition Same string constraints; matches id, rawKey, localName, or qualifiedName Same methods
kind imported or vanilla list / definitions / validate / render / interact

definitions() lists the filtered catalog and returns count / items for zero or multiple matches. The following screen-selection rules apply to validate, render, and interact. Some selectors may be omitted when exactly one candidate remains. Multiple candidates produce CLI_DEFINITION_AMBIGUOUS; no candidate produces UI_DEFINITION_NOT_FOUND. Screens are not selected by guessing their names. Without kind, the higher-precedence record wins for the same file and qualifiedName. A recommended definition in typed-state diagnostics does not create missing definitions in an arbitrary pack.

3. Common Node SDK contract

import { createRenderer, JsonUiApiError } from './local-node/api.mjs';
const renderer = await createRenderer({ language: 'en' });
try {
  await renderer.import({ pack: 'C:\\packs\\example.mcpack' });
  const result = await renderer.render({
    file: 'ui/example.json', definition: 'example.screen',
    format: 'json', frame: 0, strictSemantics: true,
  });
  console.log(result.quality);
} finally {
  await renderer.close();
}

All methods return Promises. Except for close(), their optional second argument is { signal: AbortSignal }. A signal passed to createRenderer() applies only to initialization. Subsequent operations take their own signals. Passing a request or signal to close() is outside its contract.

Requests must be ordinary JSON-equivalent objects. Unknown fields, undefined, functions, nonfinite numbers, cycles, getters, symbol keys, sparse arrays, custom array properties, nonplain object instances, and __proto__ / prototype / constructor keys are rejected. Requests are copied at admission; later mutations to the caller's object do not change the admitted operation.

Public method Accepted first-argument fields; all other fields are rejected
createRenderer() settings, language
import() pack, vanilla, resourcePack
list() kind
definitions() file, definition, kind
status() None / {}
validate() Selectors + settings, state, strictSemantics
render() Selectors + settings, state, format, width, height, uiScale, fps, frame, allowPartial, strictSemantics, strictAnimation, drawEvidence, frameSummary, uiInstanceId, localToggleState
interact() Selectors + settings, state, width, height, uiScale, fps, frame, uiInstanceId, localToggleState, expectedRevision, nodeId, event, inputSource
resolveSound() soundId, selectionSeed, contextSampleRate
close() None

strictAnimation is render-only. Interact internally requires strict semantic checks and does not accept a strictSemantics field itself. resolveSound() does not accept arbitrary file paths, settings, or audio bytes.

Creation, imports, and listing

language is ja or en, defaulting to ja. settings follows the next section. Import requires at least one of pack and vanilla; the SDK requires an absolute OS path string, at most 32,768 characters. resourcePack is an RP UUID used with pack.

SDK import replaces the entire stack. import({pack}) does not retain a previously imported vanilla layer. Specify both layers each time if both are needed. CLI import instead replaces only the supplied layers and retains unspecified layers.

Success schemas are jsonui-api-import-v1, jsonui-api-list-v1, jsonui-api-definitions-v1, and jsonui-api-status-v1. Import returns sources with kind/name/size_bytes/checksum_sha256 and, where applicable, resource_pack_uuid, plus file_count, definition_count, and diagnostics. Lists return count/items/diagnostics. Status returns import state, pending operations, Worker information, capabilities, and raster-backend availability. The status request itself is included in pending while it executes.

4. Settings and CLI mappings

createRenderer({settings}) defines instance defaults. Settings supplied to validate/render/interact merge for that call only; they are not saved for later requests. CLI settings --file merges and saves settings into its session. Top-level dimension/timing request fields override the corresponding settings values.

Numeric settings also coerce numeric strings. SDK top-level fields such as width/height/fps/frame require JSON numbers. Unknown settings keys are rejected. Separate runtime maps being below 1 MiB does not remove the additional 1 MiB combined-frame-state limit.

uiScale:'auto' uses calibration in the RP's build-info.json or the Classic default scale of 4. Width and height describe physical output pixels; logical_width/logical_height describe the canvas before scaling. This does not detect smartphone GUI scale or touch layout.

5. Typed state

state is preview JSON, not live game state. Normalization validates the entire input and does not partially apply invalid state. Accepted top-level keys are:

mockData, collectionData, furnace, brewing, trade, form, messageContext, inventory, slots, anvil, enchanting, horse, book, font_profile, eventFactorySelections.

The names differ: raw values in state use mockData/collectionData; raw settings use mock_data/collections. Supplying state replaces default runtime data and clears variables/scroll/local state. In the same request, settings containing mock_data/collections/variables/scroll/event_factory_selections/local_toggle_state cause API_STATE_CONFLICT, even if those fields are empty. Nonruntime settings such as dimensions and language can be combined with state.

State can be combined with explicit uiInstanceId/localToggleState; these are applied after typed-state normalization. Explicit fields cannot be combined with ui_instance_id/local_toggle_state in settings.

State branch Input structure and limits
mockData Binding-value object. __collections is forbidden; use collectionData
collectionData Collection name → array of row objects. A row's __collections contains nested collections
inventory main up to 27, hotbar 9, armor 4, offhand 1, container up to containerSize. containerSize is 1–256, default 27
slots Arbitrary collection name → item/null array; at most 128 collections, each up to 256 rows
furnace progress/fuel in 0–1; input/fuelItem/output are items
brewing progress/fuel/bubbles in 0–1; input/fuelItem and up to 3 output items
anvil input/material/output are item/null; name/costText strings; costRed/costGreen/invalid booleans
enchanting input/lapis item/null; up to 3 offers containing runes/cost/hoverText strings and available boolean

book title/author strings, up to 256 page strings, editable boolean
trade Up to 256 offers, each with required input/output items, optional secondInput item/null, unlocked/available booleans. title/tierName strings; selected is a zero-based integer within range, default 0. Empty offers require selected:0
form ActionForm or ModalForm described below
messageContext Requires form; locale identifier and explicit translations object
font_profile bitmap or observed-smooth
eventFactorySelections Explicit factory branch mapping corresponding to settings

Item fields are id/count/name/texture/atlasKey/variant/selected. Count is an integer 0–999, default 1; selected is boolean. Texture is a safe pack-relative textures/... reference. Texture and atlasKey are mutually exclusive. Variant requires atlasKey and is an integer 0–4,095. Unknown IDs produce diagnostics instead of being substituted with an arbitrary known item. Branches supporting empty slots normalize null or omitted trailing entries into empty rows. Supplying a renderable item does not establish native slot admission or recipe behavior.

Common limits are 1 MiB of UTF-8 JSON, depth 24, 20,000 elements, 65,536 characters per string, 256 rows per collection, 128 collections per map, and 2,048 rows total including nested collections. Raw mockData/collectionData are applied after typed branches and may explicitly override the same keys.

Interact is a stateless projection with caller-owned state. It does not store the latest UI session on the server. Each request projects the supplied definition/state/local state and evaluates an input. Required fields are uiInstanceId/nodeId/expectedRevision and enough selectors to identify one definition.

9. ResolveSound and audio

SoundId identifies a sound registered in sounds/sound_definitions.json: at most 256 characters, no control characters or $/#. SelectionSeed is an optional string up to 256 characters, default empty. ContextSampleRate is an integer 8,000–192,000, default 48,000.

Definitions resolve from imported first, then vanilla if the imported layer does not own that ID. Sound files are searched independently, imported then vanilla. If a higher layer contains no candidate for the referenced path, the same reference may resolve from a lower layer. An existing higher-layer format conflict, ambiguity, unsupported file or failed preflight is not bypassed by falling back. Definition and file ownership can differ, and the result records both. An explicit extension selects that format. Extensionless names require a unique OGG/WAV file with that stem.

Supported files are short Ogg Vorbis and WAV PCM16. Limits: encoded sound 4 MiB, duration 10 seconds, mono/stereo, 8,000–192,000 Hz, PCM reservation 8 MiB. Definitions are limited to 8 MiB/50,000 IDs/64 candidates per sound. Streaming, FSB, MP3, Opus, and chained OGG are unsupported. Candidate pitch is 0.5–2, volume is a nonnegative finite number, and weight is an integer 1–1,000,000. Definition-level volume/pitch is unsupported by this resolver.

Multiple candidates use soundId and selectionSeed in the deterministic SHA-256 weighted policy sha256-weighted-v1. This does not claim parity with Bedrock's RNG. OGG preflight checks headers/pages/CRC/sequences/packets/EOS/duration/PCM reservation. It is not a complete Vorbis decoder or a hard cap on native decoder allocations.

The result is schema:'jsonui-api-sound-v1', ok:true, a sound object using jsonui-sound-v2, playback:'not_executed', and native_equivalence:'not_evaluated'. Sound metadata includes definition/file pack IDs and paths, codec/container, channels/sampleRate/duration, encodedBytes, contentRevision as file SHA-256, candidate/index/selection policy, volume/pitch/category/is3D, and warnings. No audio bytes are returned; SDK/HTTP/CLI do not play through speakers.

The GUI player separately attempts browser decode/playback. Game category mixing and positional/distance audio are not applied and remain warnings. AudibleVerified/nativeVerified/gameMixerVerified remain false. Inspection or successful decoding alone does not certify that playback was heard.

12. Internal processing and rendering scope

  1. Inspect archive sizes/entries/paths/CRC and register the input for processing.
  2. Build UI/variable/asset catalogs; choose the precedence layer and one definition.
  3. Project inheritance, controls, variables/defaults/conditionals, supported modifications, and explicit factory branches while retaining provenance and dependency diagnostics.
  4. Run model validation and recorded native-property checks.
  5. Evaluate explicit mock/collection/local state and absolute animation time, then generate layout boxes/frame IR.
  6. Return IR for JSON or its layout diagram for SVG. PNG loads pack assets/localization/fonts, measures them, reflows where necessary, and rasterizes the final frame.
  7. Return final quality/diagnostics/digests. File output and session persistence are separate CLI/caller responsibilities.

The ordinary palette contains screen/panel/collection_panel/label/button/dropdown/image/input_panel/stack_panel/grid/scroll_view/edit_box/toggle/scroll_track/scrollbar_box. Recognition and preservation of custom/factory/tooltip_trigger does not mean generic reproduction of all associated runtime behavior. Unknown fields survive in the model, but faithful drawing of unsupported features is not guaranteed. A model parsed from JSONC does not retain comments; projected/generated output is not byte-identical source preservation.

Bindings evaluate the implemented subset of public global/collection/view conventions using explicit state. Opaque game renderer data, full Molang, and values generated by native controllers are not executed. Collection_index must match the immediate collection owner and row context; an intervening ordinary panel is not bypassed by searching arbitrary ancestors.

Images use supported pack resources such as PNG/JPEG, texture sidecars, and implemented UV/nine-slice drawing contracts. Strict PNG stops when real font assets are missing instead of silently using OS fonts to hide missing resources. Bitmap and observed-smooth profiles are explicit; the latter is an observed approximation. Proprietary Minecraft font/texture/model collections are not bundled in the public release.

Native-renderer previews include bounded safe surrogates for implemented item/progress/model cases. Resource-backed player/horse/book 3D previews are deterministic orthographic snapshots, not the full Bedrock shader/lighting/Molang/render pipeline. Missing geometry/textures, unsupported features, and resource limits are diagnosed.

Animation implements supported alpha/offset/size/uv/color/wait/flip_book cases, finite next chains, and absolute-time sampling. Easing includes linear plus in/out/in_out variants of quad/cubic/quart/quint/sine/expo/circ/back/elastic/bounce. Limits: 2,048 definitions and tracks each, chain 64, aggregate definitions 2 MiB. Event side effects, activation/reset state, and native timing when an element becomes rendered have separate unsupported diagnostics.

JSON UI Workbench 0.16.1 — Limitations and cautions

日本語: 注意事項・対応範囲 · User guide · Technical specification

This document explains what a preview can and cannot establish. The target is Classic JSON UI for Minecraft: Bedrock Edition. The tool evaluates supported features outside the game, using the state and assets you provide.

1. Classic UI only; smartphones are unsupported

This tool targets Classic UI development on desktop systems. Running the tool on a smartphone, or rendering and testing Pocket or touch-oriented UI, is unsupported. Use a desktop environment with Node.js and local file access.

UI identified as Pocket can be listed and inspected as source, but its preview stops with POCKET_PREVIEW_BLOCKED. Setting the viewport to phone dimensions does not reproduce Pocket layout, touch input, device safe areas, or other mobile behavior.

This is a limitation of the renderer. It does not, by itself, determine whether Minecraft on a particular mobile device offers a Classic profile or whether an individual add-on works there. Treat the Classic/Pocket profile, device, and input method as separate conditions.

OreUI and Script API Data-Driven UI (DDUI) execution and rendering are also unsupported. Changing a local toggle with interact() does not execute DDUI Observables or reactive forms inside Minecraft.

4. State, interactions, and animation boundaries

Forms, variables, collections, scroll positions, and time are supplied preview state. They are not necessarily the latest state read from Minecraft. If a title, body, row, or button changes in the game, provide the required state and inspect multiple previews.

interact() can update supported local toggles while retaining a form descriptor and uiInstanceId. This does not prove successful native input without closing and reopening the game form. Pass the returned localToggleState to the next request. Do not use saved local state to override an externally bound control or mix state from another UI.

expectedRevision checks consistency with the state supplied in the request. The server does not keep the latest snapshot, so an old snapshot paired with its old revision can be replayed. The caller must store the latest state and manage concurrent users when needed.

The interaction API applies only localTogglePatch. Described navigation, form submission, clipboard, or other effects are not executed by that API. It is not a drag/key replay system or a reproduction of the game's input loop. The GUI has individual interaction paths whose execution scope need not match API effect descriptions.

Animation is sampled at the requested time and event conditions. Native screen creation, clocks, event order, side effects, input latency, and server synchronization are unverified. Recorded combinations of looping on uv / size / offset, and some flip_book attachments, retain compatibility diagnostics. Successful numerical sampling does not remove those diagnostics.

5. OGG, WAV, and audible playback limits

Registered sound IDs resolve to assets in loaded packs. resolveSound() is not an arbitrary OS file reader and does not return audio bytes or play through speakers.

Supported short sounds are OGG Vorbis or PCM16 WAV, 1 / 2 channels, 8,000–192,000 Hz, and no longer than 10 seconds. Additional limits include a 4 MiB encoded file and an 8 MiB decoded PCM reservation. Even a sound under 10 seconds can be rejected because of its reservation, packet count, structure, or another limit.

Opus, FSB, chained OGG, and long streaming playback are unsupported. Renaming a file to .ogg does not convert it to Vorbis. If OGG and WAV share an ambiguous sound name, specify the extension in the sound definition.

Browser playback in the GUI does not reproduce Minecraft category volume sliders or positional 3D audio. Relevant definitions report AUDIO_PREVIEW_CATEGORY_MIXER_NOT_APPLIED / AUDIO_PREVIEW_POSITIONAL_NOT_APPLIED. Weighted candidate selection need not match the game's random sequence. Supported combined pitch is 0.5–2, output gain is capped at 1, and the GUI has a separate preview volume control.

Audio permission, disabled preview audio, zero volume, preparation time, decoding failure, concurrent voice limits, or memory budgets may prevent playback. Resolving an asset, passing format inspection, or requesting Web Audio playback does not prove sound was heard through speakers. Audible browser and native audio were not verified for this release.

6. Textures, fonts, items, and 3D models

The public source does not bundle Minecraft / Mojang textures, fonts, audio, skins, models, or complete UI. Load necessary bases and assets from appropriately licensed reference packs matching the target game version. Pack priority, content, language, UI scale, and viewport dimensions can change the result.

Missing assets or required inputs produce diagnostics. Strict PNG output does not fill missing assets with unrelated images and call the result complete. JSON / SVG bounds alone need not match PNG's final glyph measurement and reflow, native font metrics, or game layer order.

Numeric item ID tables depend on the target version. Not every custom item, auxiliary value, NBT state, dye, enchantment, or dynamic appearance is reproduced. If an item reports NATIVE_ITEM_MODEL_REQUIRED, do not interpret a face texture as a finished item icon.

Supported player / horse model paths are not a renderer for every entity's game pipeline. Player previews use model and skin data from reference packs; they do not automatically retrieve the user's account skin. Cameras, materials, controllers, and states outside the implementation are diagnosed or unsupported.

looping on specific animation types and related cases Compatibility uncertainty in animation quality. Not a blanket ban on every looping or flip_book.

This is not a complete schema validator that prohibits every unknown property. Absence of a diagnostic does not establish that all properties, including those in future game versions, are valid.

Binding resolution through a global fallback and missing collection context can report concerns independently from successful calculation. Scanning and observation limits produce unknown or incomplete-observation evidence. Omitted diagnostics do not mean no issues exist.

8. Large UIs, editing, and outputs

Node counts, generated controls, depth, draw rectangles, image memory, request time, and response size are bounded. Major examples include 50,000 model nodes, 5,000 PNG rectangles, 8,192 px per PNG dimension, 16 Mi pixels total, and a 24 MiB frame response. These are renderer budgets, not Minecraft UI capacity limits or FPS guarantees. See the technical specification for the full list and scope.

--frame-summary requests a JSON summary of a large frame. It does not return full diagnostic text, a renderable frame, or PNG, and it does not bypass generation or evaluation limits. Passing each isolated part of a screen does not substitute for passing the entire screen.

Experimental GUI edits can affect multiple controls using the same shared definition. A generated cell may have no independent source. Moving, deleting, or detaching inheritance cannot always be applied independently to any chosen element. Distinguish draft review, committing to source, and export.

Source undo / redo is bounded and does not reverse every preview click, settings change, or UI selection. CLI source history retains at most 64 entries / 8 MiB, with an additional session-wide limit. Dropped history or an oversized individual edit can make undo unavailable.

The design keeps original archives unchanged and writes to a separate output. Still inspect source, diagnostics, and reimported output to confirm the intended result. Do not bypass output protections to write over the input.

9. Before publishing an add-on

  1. Record the game version, Classic profile, input method, reference pack, language, dimensions, and UI scale.
  2. Inspect necessary states after buttons, toggles, rows, scrolling, and animation time change, as well as the initial screen.
  3. Apply strict options to the scope you intend to check. Read quality, missing information, unknown, and any partial-render indicators.
  4. Separately check game display, input, form responses, scripts, inventory, and audio in Minecraft and its Content Log when relevant.
  5. Inspect code and assets included in the distribution and the contents of shared diagnostic files. Diagnostics can contain pack content, names, and local paths.

These steps distinguish what the renderer output establishes from what requires in-game confirmation.
