# JSON UI Workbench 0.15.0 — 実験版 GUI 起動ガイド

0.15.0 の標準入口は CLI です。`npm start` は CLI ヘルプを表示して終了します。
このファイルは `npm run gui`、`start.bat` / `start.cmd` / `start.sh` で明示的に
起動する実験版 GUI の説明です。[CLI / API の現行入口](../docs/release/ENTRYPOINTS_JA.md) と
区別してください。GUI 編集は未完成で、CLI / API にこの画面の起動は不要です。

r41 / 0.13.6 を基にした公開ソース版です。[現在の製品説明](../README.md)、[素材の方針](../docs/release/ASSET_POLICY.md)、[GitHub 公開手順](../docs/release/GITHUB_JA.md) を参照してください。

初回は Node.js 22.14.0 以降を通常の方法で用意し、プロジェクトのルートで `npm ci --ignore-scripts`、続いて `npm run gui` を実行する方法を推奨します。PNG 用の任意依存を取得します。

ZIP を短い書き込み可能なフォルダーへ全部展開し、`start.bat` をダブルクリックしてください。ZIP の中から直接起動しないでください。既存の `start.cmd` も同じ入口として使用できます。

旧版から更新する場合は、旧版の起動ウィンドウで `Ctrl+C` を押して終了し、新しいZIPを別の空フォルダーへ展開してください。そのフォルダーの `start.bat` を実行し、パックを選び直します。

Node.js 22.14.0 以上が PATH にあれば、その Node.js を使用します。準備完了後に既定のブラウザを開きます。Node.js がない、または古い場合は、Windows 11 標準の curl.exe と certutil.exe を使用して、このアプリ専用の Node.js 24.21.0 を公式配布元から取得します。通常の起動と初回準備に PowerShell スクリプトは不要です。Node 本体の補助取得に管理者権限は不要です。ただし公開版には PNG 用のバイナリを同梱していないため、PNG が必要な場合は npm を含む通常の Node.js を用意し、`npm ci --ignore-scripts` を実行します。

起動ウィンドウを開いたまま使用します。終了するときはそのウィンドウで `Ctrl+C` を押してください。同じフォルダーの `start.bat` をもう一度開いた場合は、起動済みのサイトが実際に応答することを再確認してから開きます。通常はポート 3210 を使用し、他のプログラムが使用中なら空きポートを選びます。URL は起動ウィンドウにも表示します。

コマンドで処理する場合の説明は `local-node/CLI-ja.md` にあります。パックの読込・編集・PNG 出力・選択書出し・パック名やアイコンの設定・診断保存を実行できます。PNG 描画バックエンド `@napi-rs/canvas` は公開ソースにバイナリを同梱せず、npm から固定版を取得します。CLI の `status` に表示される `capabilities.png` が `false` の場合は、バックエンドを読み込めていないことを示します。

## 初回準備

- 専用実行ファイルは `.jsonui/runtime/node.exe` へ保存します。Windows x64 と ARM64 を区別します。
- 補助経路は standalone `node.exe` だけを取得し、npm は導入しません。PNG 用依存の導入には npm を含む Node.js 環境を使用してください。
- 配布元とバージョンと SHA-256 を固定しています。照合が完了するまで実行しません。
- 保存前の不完全ファイルは別の一時フォルダーに置きます。途中で失敗した場合、完了済みの Node として採用しません。`runtime` に空フォルダーや不完全な項目が残っていた場合も、削除せず `.jsonui/bad-*` へ保管してから再取得します。ネットワーク失敗後は同じ `start.bat` で再試行できます。
- 既存のシステム Node.js、PATH、レジストリ、元のリソースパックは変更しません。
- 初回取得中は curl の進捗を表示します。ネットワーク試行は最大 2 回、1 回あたり全体 180 秒、接続待ち 30 秒に上限があります。curl.exeまたはcertutil.exeがない特殊な環境では PowerShell 5.1 の補助処理へ移り、受信の経過時間 180 秒と個々の通信待ち 30 秒を上限とします。補助処理は通信ごとに残り時間を計算し、その残り時間を超えて受信を待たないようにします。ファイル保存・SHA-256 照合などの時間は通信待ち時間とは別です。
- 受信完了後は `SETUP_VERIFYING` と表示して SHA-256 の検証へ進みます。PowerShell の補助処理では総バイト数が分かる場合に受信率・受信量・経過秒を表示し、総量不明時は受信量と経過秒を表示します。受信 100% は初回準備全体の完了を意味しません。
- 対応 Node の判定と専用 Node の SHA-256 照合は、確認処理が終了コード `0` を返した場合だけ採用します。Windows の確認用プログラムが負の終了コードで異常終了した場合も成功として扱いません。
- 呼び出し元に `ERRORLEVEL` という環境変数が設定されていても、実際の終了値を隠さないようBAT内の局所環境で解除します。起動元の環境は変更しません。

macOS/Linuxで `bash start.sh` を使用する場合も、対応Nodeの確認後、同じ起動管理・準備確認・重複起動の再利用を通ります。この入口からNodeを自動取得する機能はありません。

## 起動できない場合

`local-node/START-ja.md` がこの説明です。アプリ起動の記録は `.jsonui/launcher.log`、初回準備の記録は `.jsonui/bootstrap.log` にあります。各ログは 1 MiB を超えた次回起動時に前回分へ移し、通常は 2 世代で保持します。API の認証トークンは起動ログへ書きません。Nodeの警告・失敗は標準エラー出力にも出します。タイムアウトや初期化未完了を正常起動として記録しません。

- **curl.exeまたはcertutil.exeがなく、補助スクリプトも禁止されている:** 通常の Windows 11 の経路では発生しません。curl.exeまたはcertutil.exeがない場合に使用する PowerShell が `bootstrap.ps1` を開始する前に拒否した場合、PowerShell 側の記録は作成されません。本アプリは実行ポリシーや署名要件を変更しません。使用端末のルールに従って Node.js 22.14.0 以上を通常の方法で用意した後、同じ `start.bat` を実行してください。既存 Node からの起動は PowerShell スクリプトを使用しません。
- **`SETUP_PACKAGE_INCOMPLETE`（終了コード22）:** ZIPの展開に必要ファイルが不足しています。Nodeの再取得は開始しません。ZIP一式を短い書き込み可能なフォルダーへ全部展開し、その中の `start.bat` を実行してください。
- **`SETUP_FALLBACK_FAILED`:** PowerShell による補助処理またはその後の起動が終了しました。原因は直前の詳細コードとログで確認します。通信、照合、起動、スクリプト実行制限のいずれかを、このコードだけで断定しません。
- **`LAUNCH_STATE_UNAVAILABLE`:** 起動記録フォルダー `.jsonui` を用意できません。そこに同名のファイルが存在する場合や、展開先へ書き込めない場合が考えられます。元の項目は変更せず終了します。短い書き込み可能な別のフォルダーへZIP一式を展開して起動してください。
- **`LAUNCH_LOG_UNAVAILABLE`:** 起動ログを書き込めませんでした。起動ウィンドウへ1回だけ通知します。サイトが開いている場合は使い続けられますが、必要なら画面の記録を保存してください。
- **`SETUP_SHA256_MISMATCH`（BAT終了コード24）:** ダウンロード内容が固定の公式ハッシュと不一致でした。実行を中止しています。ネットワーク経路を確認して再試行してください。
- **`SETUP_EXISTING_RUNTIME_INVALID`（BAT終了コード23）:** 保存済みの専用 Node が検証できず、別名で保管する処理にも失敗しました。実行中のアプリ専用 Node やフォルダーの書き込み権限を確認してください。通常は破損した専用 Node、空の `runtime` フォルダー、同名の不完全なファイルを `.jsonui/bad-*` に保管して公式版を自動再取得します。保管済みファイルは実行・自動削除しません。
- **`SETUP_ALREADY_RUNNING`（PowerShell 補助処理）:** 別の初期設定が進行しています。先に開いたウィンドウを確認してください。待機は 30 秒で終了します。完了後は同じ BAT で起動できます。
- **`LAUNCH_START_TIMEOUT`:** サイト初期化が15秒で完了しませんでした。起動管理を解放し、遅れて作成されたサーバーも閉じます。同じ BAT を再実行してください。
- **`LAUNCH_HEALTH_TIMEOUT` / `LAUNCH_NOT_READY`:** サイトの準備完了を通常5秒以内に確認できませんでした。応答が途切れた場合や、期待する形式でない場合、64 KiB の上限を超える場合も正常起動と扱いません。この起動が作成したサーバーを閉じます。同じ `start.bat` で再試行できます。
- **`LAUNCH_CLOSE_TIMEOUT` / `LAUNCH_CLEANUP_FAILED`:** サーバーや起動管理口の終了処理が通常10秒で完了しませんでした。起動失敗後の後始末にも同じ期限を設けており、元の起動エラーを残したまま終了処理の失敗を別に記録します。先に開いた、このフォルダーの起動ウィンドウを終了してから再実行してください。期限到達を終了成功とは扱いません。
- **`LAUNCH_INSTANCE_UNAVAILABLE`:** 既存の起動管理口は応答しましたが、サイト本体の準備完了を再確認できませんでした。先に開いた、このフォルダーの JSON UI 起動ウィンドウで `Ctrl+C` を押して終了し、同じ `start.bat` を再実行してください。別の Node.js アプリや他のプログラムを終了する必要はありません。
- **`LAUNCH_WAIT_INVALID`:** 起動モジュールに不正な待機時間が渡されました。通常の `start.bat` は固定の正しい値を使うため、設定は不要です。起動用コードを変更した場合は、配布時のファイルに戻して再実行してください。
- **`LAUNCH_INSTANCE_BUSY`:** 起動済み、または起動途中の管理口が応答しません。先に開いた JSON UI の起動ウィンドウを確認し、必要ならそのウィンドウで終了してから再実行してください。他のプログラムを自動終了しません。
- **`LAUNCH_PATH_LONG` / `SETUP_PATH_LONG`:** フォルダー名を含む完全パスが長すぎます。短い書き込み可能な場所へ全部展開し直してください。長いパスを許可する Windows 設定の変更は要求しません。
- **ブラウザだけ開かない:** 起動ウィンドウに表示された `http://127.0.0.1:.../` をブラウザで開いてください。サイト自体は起動したままになります。

エラー後にダブルクリックしたウィンドウが閉じてしまう場合は、展開フォルダーでコマンドプロンプトを開いて `start.bat` を実行すると、表示を確認できます。無人実行を停止させる `pause` は使用していません。

## 起動後の表示とデータ

原本リソースパック・実機画像・完全なフォント一式はアプリに同梱していません。対象版のバニラ参照パックと編集対象パックを別途指定してください。パックとJSON内の定義を選ぶと、Nodeが保持する投影情報から解釈・binding・アニメーション・レイアウトの中間表現を作成します。ブラウザは文字・素材寸法の補正とCanvas描画を担当します。初回も投影IDを送り、同じ大型モデルの転送を繰り返しません。Node最終ピクセル描画ではありません。

上部のイベントと再生・停止・先頭・1コマ・時間指定で動きを確認します。「状態データを編集」からJSONを読込・編集し「状態を適用」で反映できます。Pocketは読込と一覧取得が可能ですが、プレビューは拒否します。

表示の準備中や失敗理由は画面へ表示します。通信失敗は「表示を再計算」、投影情報の世代が失効した場合はファイルとUI定義の再選択で復旧します。

## 起動後のデバッグ記録

サイト上部の「ログを一括保存」で、初回準備・起動・Node処理・ブラウザ診断をまとめたJSONをダウンロードできます。サイトが開けない場合は上記の `.jsonui/bootstrap.log` と `.jsonui/launcher.log` を確認します。

起動ログでは `launch_run_id` と `sequence` で1回の起動内の順序を追えます。`LAUNCH_RUNTIME` には Node の版・OS・CPUアーキテクチャ・ブラウザ自動起動設定を、`LAUNCH_STAGE_COMPLETED` / `LAUNCH_STAGE_FAILED` には段階・所要時間・期限と失敗コードを記録します。初期化待ちと実際の処理時間を混同しないため、処理中の表示に推定の全体%は付けません。

サイト診断の例外には明示的な `code`、`category`、`retryable`、`correlation_id` を残します。`retryable: false` は再試行の可否として維持し、自動再試行は行いません。取消が明示された診断は `cancelledCount` に集計し、失敗件数と分離します。未分類の `AbortError` やメッセージに取消という語があるだけの例外は、取消と断定しません。ログは既存の容量上限と本文・認証情報の除去を維持します。

0.6.0では、Nodeで取り込んだパックから開いたUIの参照検査もNode側で処理します。ログの `validation` はこの検査の実行・再利用回数、`zip_io` はZIPの読取回数と少量キャッシュの保持量です。取込時の5文書確認は0.5.1の順番待ち制御を維持しており、読取枠が空くまで待機します。これらの数値は処理の記録であり、実機と表示が完全一致したことを示す合格点ではありません。

## 任意の設定

通常は設定不要です。コマンドプロンプトから設定する場合のみ、以下を使用できます。いずれも現在のコマンドプロンプトの範囲です。

```cmd
set "JSONUI_PORT=3211"
set "JSONUI_NO_BROWSER=1"
start.bat
```

`JSONUI_PORT=0` は空きポートの自動割り当てです。`JSONUI_NO_BROWSER=1` はブラウザの自動起動だけを止めます。Windows BAT の公開先は `127.0.0.1` に固定します。

## 検証範囲

今回、Windows 実機で BAT / PowerShell / ブラウザ起動を実行する環境はありません。Node.js の起動管理は Linux 上で実際の HTTP サーバーを用いて検査しました。既存サイトが停止した状態からの二重起動、応答形式の不一致、過大な応答、途中で止まった応答、初期化失敗後の再起動も検査しました。Windows の curl / certutil / 実行ポリシー、既定ブラウザ、実際の初回ダウンロード、空runtimeからのネイティブ復旧、x64 / ARM64 の実行、ネイティブのパイプと Ctrl+C の動作、負の終了コード、PowerShell の受信期限は **未実施（NOT_RUN）** です。すべての Windows 環境で初回設定まで成功すると保証するものではありません。

終了処理が未完了のPromiseを返し続ける場合は、通常の終了でも起動失敗後でも期限を設けて診断を返します。ただし、JavaScriptの同期処理やOS自体が停止してタイマーを実行できない場合、この期限だけで強制終了できるとは限りません。また、BATが最初に行うPATH上のNodeの版確認には独立したwatchdogがありません。Nodeプロセス自体の停止まで有限時間で解消できるという保証には含めていません。

## 0.12.3の起動前ファイル確認

`start.bat` / `start.cmd` はNodeを確定した後、サーバーや画面を起動する前に `preflight28.cjs` を実行します。配布manifestに列挙した258件の必須ファイルが、存在する空でない通常ファイルか、実体がパッケージ内かを確認します。欠落・空ファイル・外部リンクは `LAUNCH_PACKAGE_INCOMPLETE` 等として停止します。

これは存在・種別の確認であり、全ファイルのSHA検証や構文検査ではありません。ソースを変更して使用することは妨げません。配布時と同じバイト列か確認する場合は、ルートの `package-manifest.json` とSHA一覧を使用してください。

Windows実機でBATを動かしたという意味ではありません。今回のBAT/CMD一致、文字コード、パス処理、失敗ゲートはコードと自動検査で確認しました。
